# 认证与授权模块（auth）

## 1. 模块概述

### 1.1 定位

`auth` 模块是 ASA 系统的安全入口，负责管理员初始化、用户登录/退出、会话管理、CSRF 防护、角色校验和项目级数据权限控制。

### 1.2 设计依据

- `docs/1_PRD/自动化安全评估系统-PRD.md`
- `docs/3_概要设计/自动化安全评估系统-概要设计总纲.md` — 第 5.2 节、第 8.1 节、第 10.3 节
- `docs/4_开发规范/API接口文档.md` — 第 4 章（系统与认证接口）
- `docs/4_开发规范/后端/后端开发规范.md` — 第 8 章（认证、授权与审计）
- `docs/4_开发规范/数据库/数据库设计.md` — `users` 表设计

### 1.3 职责边界

| 职责 | 说明 |
| --- | --- |
| 系统初始化状态查询 | 供前端判断展示初始化页还是登录页 |
| 管理员初始化 | 首次使用时创建唯一初始管理员，使用全局 advisory lock 防并发 |
| 用户登录 | Argon2id 密码校验，签发短期 Cookie 会话 |
| 用户退出 | 服务端会话失效，清除认证 Cookie |
| 会话校验 | 解析 `asa_session` Cookie，注入当前用户到请求上下文 |
| CSRF 防护 | 校验写操作的 `X-CSRF-Token`，恒定时间比较 |
| 角色权限 | 区分 `user` 和 `admin`，管理员仅对系统配置有额外权限 |
| 项目数据权限 | 普通用户只能访问本人创建的项目，所有子资源查询附加 `created_by` 条件 |
| 审计记录 | 初始化、登录成功/失败、越权访问写入审计日志 |

**不负责：** 多租户隔离、统一身份认证（OAuth/OIDC）、用户自助注册、密码重置——这些不在 MVP 范围内。

## 2. 架构与依赖

### 2.1 在架构中的位置

```text
浏览器 → Nginx → FastAPI API (routers/v1/auth)
                      │
                      ├── 领域层 (domain/auth/)
                      │     ├── User (聚合根)
                      │     ├── AuthenticationService (密码校验、会话签发)
                      │     └── AuthorizationPolicy (角色 + 项目权限)
                      │
                      ├── 应用层 (application/)
                      │     ├── commands/InitializeSystem
                      │     ├── commands/Login
                      │     ├── commands/Logout
                      │     └── queries/GetSystemStatus
                      │
                      └── 基础设施层 (infrastructure/)
                            ├── database/ (UserRepository)
                            ├── security/ (Argon2idHasher, SessionStore, CSRF)
                            └── audit/ (AuditLogger)
```

### 2.2 依赖方向

- `domain/auth` 不依赖任何框架、ORM、Redis 或 HTTP。
- `application` 通过 Port 接口依赖 `UserRepository`、`PasswordHasher`、`SessionStore`。
- `infrastructure` 实现 Port，不决定认证流程。
- `routers/v1/auth.py` 只解析请求、调用应用用例、返回统一响应。

### 2.3 涉及的数据库表

| 表 | 角色 |
| --- | --- |
| `users` | 保存用户标识、小写用户名、Argon2id 哈希、角色和账户状态 |
| `audit_logs` | 记录初始化、登录成功、连续登录失败、越权访问 |

### 2.4 涉及的 API 接口

| 接口 | 方法 | URL | 说明 |
| --- | --- | --- | --- |
| 查询系统初始化状态 | `GET` | `/api/v1/system/status` | 无需认证 |
| 初始化管理员 | `POST` | `/api/v1/system/init` | 无需认证，仅未初始化时可用 |
| 用户登录 | `POST` | `/api/v1/system/login` | 无需认证 |
| 用户退出 | `POST` | `/api/v1/system/logout` | Cookie 会话认证 |

## 3. 领域模型

### 3.1 用户实体

```text
User
├── id: UUID                          # 用户标识
├── username: str                     # 小写登录名，1-64 字符，无空白
├── password_hash: str                # Argon2id 哈希
├── role: "user" | "admin"           # 角色
├── status: "active" | "disabled"    # 账户状态
├── created_at: datetime             # 创建时间
└── updated_at: datetime             # 更新时间
```

### 3.2 用户状态机

```text
[创建] → active
active → disabled  (管理员操作，MVP 暂未实现接口)
```

MVP 不提供用户删除和状态变更接口，但数据库预留 `status` 字段支持后续扩展。

### 3.3 业务规则

| 规则 | 实现位置 | 说明 |
| --- | --- | --- |
| 系统只能初始化一次 | 领域服务 + 全局 advisory lock + 事务 | 并发创建多个初始管理员被数据库互斥阻止 |
| 用户名转小写写入 | 应用层 | 数据库唯一约束 `uq_users__username` 兜底 |
| 密码最小长度和强度 | 应用层校验 | 具体策略由安全评审确定 |
| 登录失败统一返回 `INVALID_CREDENTIALS` | 应用层 | 不区分用户不存在和密码错误 |
| 密码校验失败路径耗时相近 | `Argon2idHasher` | 防止时序侧信道 |
| 禁用账户拒绝登录 | 领域层 | 返回 `ACCOUNT_DISABLED` |
| 会话过期返回 `SESSION_EXPIRED` | 中间件/Dependency | 与 `AUTH_REQUIRED` 区分 |

### 3.4 领域异常

| 异常 | 说明 |
| --- | --- |
| `SystemAlreadyInitialized` | 系统已完成初始化 |
| `SystemNotInitialized` | 系统尚未初始化，拒绝登录 |
| `InvalidCredentials` | 用户名或密码错误（不区分具体原因） |
| `AccountDisabled` | 账户已被禁用 |
| `AdminRequired` | 非管理员访问管理员专属资源 |
| `PermissionDenied` | 已认证但无当前资源权限 |

## 4. 认证流程

### 4.1 初始化管理员

```text
POST /api/v1/system/init
  │
  ├── 1. 校验系统未初始化（查询 users 表是否有记录）
  ├── 2. 获取全局 advisory lock（防止并发创建）
  ├── 3. 事务内再次确认未初始化
  ├── 4. 校验 username 格式、password 强度
  ├── 5. 生成 Argon2id 哈希
  ├── 6. INSERT users (role='admin', status='active')
  ├── 7. 写入审计日志（无登录态，使用请求 IP 作为操作者标识）
  ├── 8. 提交事务，释放 advisory lock
  └── 9. 返回 201 Created + UserSummary

注意：初始化成功不自动建立登录态，前端需调用登录接口。
```

### 4.2 用户登录

```text
POST /api/v1/system/login
  │
  ├── 1. 限流检查（按 IP + username 计数失败次数）
  ├── 2. 校验系统已初始化
  ├── 3. 查找用户（username 小写匹配）
  ├── 4. Argon2id 校验密码
  │     ├── 失败 → 统一返回 INVALID_CREDENTIALS，写入审计
  │     └── 成功 → 继续
  ├── 5. 检查 status != 'disabled'
  ├── 6. 创建会话（生成不可预测 session_id，存储到 Redis/DB）
  ├── 7. Set-Cookie: asa_session + asa_csrf
  │     HttpOnly; Secure; SameSite=Lax
  ├── 8. 写入审计（登录成功）
  └── 9. 返回 200 OK + UserSummary + expires_at
```

### 4.3 会话校验（Dependency）

每个受保护接口的 FastAPI Dependency 执行：

```text
Request with Cookie: asa_session=xxx
  │
  ├── 1. 提取 asa_session Cookie
  ├── 2. 从 SessionStore 查找会话
  │     ├── 不存在 → 401 AUTH_REQUIRED
  │     └── 存在但过期 → 401 SESSION_EXPIRED
  ├── 3. 查找关联 User
  │     ├── 不存在 → 401 AUTH_REQUIRED
  │     └── status='disabled' → 403 ACCOUNT_DISABLED
  └── 4. 返回 CurrentUser(id, username, role, status)
```

### 4.4 用户退出

```text
POST /api/v1/system/logout
  │
  ├── 1. 校验 CSRF Token
  ├── 2. 使服务端会话失效（幂等）
  ├── 3. Set-Cookie: asa_session=; Max-Age=0
  │              asa_csrf=; Max-Age=0
  └── 4. 返回 200 OK
```

## 5. CSRF 防护

### 5.1 Token 生命周期

- 登录成功后，服务端生成 `asa_csrf` Token 并通过 Cookie 返回。
- Token 与 `asa_session` 一一对应，会话失效时 CSRF Token 同步失效。
- 写操作（POST/PUT/PATCH/DELETE）必须在 `X-CSRF-Token` 请求头回传。

### 5.2 校验逻辑

```text
Middleware/Dependency
  │
  ├── 1. 请求方法为 GET/HEAD/OPTIONS → 跳过
  ├── 2. 提取 Cookie 中的 asa_csrf
  ├── 3. 提取请求头 X-CSRF-Token
  ├── 4. 恒定时间比较
  │     ├── 相等 → 放行
  │     └── 不等 → 403 CSRF_INVALID + 审计
```

## 6. 权限模型

### 6.1 角色权限矩阵

| 操作 | `user` | `admin` |
| --- | :---: | :---: |
| 登录/退出 | ✓ | ✓ |
| 创建项目 | ✓ | ✓ |
| 访问自己创建的项目及子资源 | ✓ | ✓ |
| 访问他人项目 | ✗ | ✗（MVP 无项目共享） |
| 查询/更新系统配置 | ✗ | ✓ |
| 停止/删除他人项目 | ✗ | ✗ |

### 6.2 项目数据权限

所有项目子资源查询（漏洞、路径、报告、日志、消息、资源、阶段、任务）必须在 SQL 查询层附加权限条件：

```sql
-- 普通用户
WHERE projects.created_by = :current_user_id

-- 管理员访问项目资源同样校验归属（MVP 不开放管理员查看所有项目）
WHERE projects.created_by = :current_user_id
```

Repository 或应用服务统一注入 `project_scope(project_id, user_id)` 条件，不在每个 Router 手写。

### 6.3 资源不存在与无权限的响应策略

统一返回 `PROJECT_NOT_FOUND`（404），避免通过差异枚举其他用户项目。

## 7. 安全实现要点

### 7.1 密码安全

- **仅保存 Argon2id 哈希**，参数：time_cost=3, memory_cost=65536, parallelism=4, hash_len=32（具体值由安全评审确认）。
- 密码不进入日志、审计、事件、响应。
- 密码校验失败路径与成功路径耗时相近（故意延迟对齐）。

### 7.2 会话安全

- `asa_session` Cookie：`HttpOnly`（防 XSS 读取）、`Secure`（仅 HTTPS）、`SameSite=Lax`（防 CSRF）。
- 会话值不可预测（使用 `secrets.token_urlsafe(32)`）。
- 会话有过期时间（由安全评审确定，建议 2-8 小时）。
- 服务端会话存储（Redis 或数据库），支持主动撤销。

### 7.3 防枚举与防暴力

- 用户名不存在和密码错误统一返回 `INVALID_CREDENTIALS`。
- 登录限流：按 IP + username 组合计数，超阈值返回 `429 RATE_LIMITED`。
- 初始化限流：按 IP 计数，防止恶意重复调用。

### 7.4 审计要求

以下事件必须写入 `audit_logs`（脱敏后）：

| 事件 | action | result_status | 说明 |
| --- | --- | --- | --- |
| 初始化成功 | `system_init` | `success` | 记录管理员用户名（不记录密码） |
| 登录成功 | `login` | `success` | 记录用户名、IP |
| 登录失败 | `login` | `failure` | 记录失败用户名（不区分是否存在） |
| 登录限流触发 | `login_rate_limited` | `denied` | 记录 IP 和次数 |
| 会话过期访问 | `session_expired` | `denied` | 记录请求路径 |
| 越权访问 | `access_denied` | `denied` | 记录资源类型和操作 |

## 8. 代码实现指南

### 8.1 Router 层

```text
apps/api/src/asa_api/routers/v1/auth.py  (系统状态、初始化、登录、退出)
apps/api/src/asa_api/routers/v1/system.py (需要时可拆分系统状态和配置路由)
```

Router 只做：参数解析 → 调用应用用例 → 构造统一响应。禁止在 Router 中直接操作数据库 Session 或 Redis。

### 8.2 领域层

```text
packages/backend-core/src/asa_core/domain/auth/
├── entities.py         # User 聚合根
├── services.py         # AuthenticationService, AuthorizationPolicy
├── exceptions.py       # 认证相关领域异常
└── value_objects.py    # Username, PasswordHash, SessionToken
```

### 8.3 应用层

```text
packages/backend-core/src/asa_core/application/
├── commands/
│   ├── initialize_system.py   # InitializeSystem Command + Handler
│   ├── login.py               # Login Command + Handler
│   └── logout.py              # Logout Command + Handler
├── queries/
│   └── get_system_status.py   # GetSystemStatus Query + Handler
└── ports/
    ├── user_repository.py     # UserRepository 接口
    ├── password_hasher.py     # PasswordHasher 接口
    ├── session_store.py       # SessionStore 接口
    └── audit_logger.py        # AuditLogger 接口
```

### 8.4 基础设施层

```text
packages/backend-core/src/asa_core/infrastructure/
├── database/
│   └── user_repository.py     # SQLAlchemy UserRepository
├── security/
│   ├── argon2_hasher.py       # Argon2id 实现
│   ├── redis_session_store.py # Redis 会话存储
│   └── csrf.py                # CSRF Token 生成与校验
└── ...
```

### 8.5 关键实现约束

- 初始化管理员的"检查未初始化"和"创建管理员"必须在**同一数据库事务 + 同一 advisory lock** 内完成。
- 用户名在写入前由**应用层转小写**，数据库 `CHECK (username = lower(username))` 作为第二道防线。
- 会话存储使用 **Redis**（支持过期、主动撤销、多进程共享），备选方案为数据库 `sessions` 表。
- CSRF 校验使用 **`hmac.compare_digest`** 恒定时间比较。

## 10. 测试要点

### 10.1 单元测试

- 用户实体创建和状态约束
- `InvalidCredentials` 异常不泄露用户存在与否
- 密码哈希和校验（相同密码 → 相同结果？不，Argon2id 每次生成不同哈希）
- 角色权限判断：`user` 不能访问管理接口，`admin` 可以
- 账户禁用后拒绝登录
- 转小写用户名规范化

### 10.2 API 测试

- `GET /api/v1/system/status` — 未初始化和已初始化两种场景
- `POST /api/v1/system/init` — 成功（201）、已初始化（409）、字段校验（422）、并发初始化只有一个成功
- `POST /api/v1/system/login` — 成功（200 + Set-Cookie）、错误密码（401 `INVALID_CREDENTIALS`）、禁用账户（403 `ACCOUNT_DISABLED`）、系统未初始化（409）、限流（429）
- `POST /api/v1/system/logout` — 成功（200）、未登录（401）、CSRF 失败（403）
- 受保护接口未登录（401 `AUTH_REQUIRED`）
- 受保护接口会话过期（401 `SESSION_EXPIRED`）
- 普通用户访问管理接口（403 `ADMIN_REQUIRED`）
- 用户 A 访问用户 B 的项目（404 `PROJECT_NOT_FOUND`）

### 10.3 安全测试

- 登录失败不暴露用户名是否存在（时间分析和响应差异）
- Cookie 属性：HttpOnly、Secure、SameSite
- CSRF Token 缺失/不匹配返回 403
- 密码和密码哈希不出现在日志、响应、审计元数据
- 会话 ID 不可预测（熵测试）
