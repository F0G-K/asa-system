# 隔离环境模块（runtimes）

## 1. 模块概述

### 1.1 定位

`runtimes` 模块负责为每个安全评估项目创建和管理独立的 Docker 隔离环境，提供受控的文件操作、命令执行和资源监控能力。该模块与 `executor` 应用紧密配合：`runtimes` 定义领域规则和执行策略，`executor` 作为独立网关进程实际操作 Docker Engine。

### 1.2 设计依据

- `docs/1_PRD/自动化安全评估系统-PRD.md`
- `docs/3_概要设计/自动化安全评估系统-概要设计总纲.md` — 第 5.2 节、第 10 章
- `docs/4_开发规范/API接口文档.md` — 第 3.3 节 ProjectDetail.runtime 字段
- `docs/4_开发规范/后端/后端开发规范.md` — 第 13 章（Executor、文件与报告）
- `docs/4_开发规范/数据库/数据库设计.md` — `project_runtimes` 表设计

### 1.3 职责边界

| 职责 | 说明 |
| --- | --- |
| 容器生命周期 | 创建、启动、停止、销毁项目级隔离容器 |
| 容器状态管理 | 追踪 `pending → starting → running → stopping → stopped/destroyed/failed` |
| 环境快照 | 记录启动时的技术栈、依赖和配置快照 |
| 受控文件操作 | 通过 Executor 提供文件读取、目录遍历、关键字搜索 |
| 受控命令执行 | 通过 Executor 执行程序名+参数数组，不拼接 Shell |
| 资源限制 | CPU、内存、磁盘、进程数和超时上限 |
| 路径安全 | 规范化路径、符号链接校验、项目根目录限制 |

**不负责：** 源码拉取（Worker 负责）、AI 角色调度（scheduler/agents）、报告生成（reports）——这些由对应模块处理。

## 2. 架构与依赖

### 2.1 控制面与执行面分离

```text
控制面（不得访问 Docker Socket）：
  API ──── 只查询 project_runtimes 表
  Worker ─ 通过 ExecutorPort 调用 Executor

执行面（只监听内部网络）：
  Executor ─ 操作 Docker Engine
           ─ 管理项目隔离容器
           ─ 提供文件/命令接口
```

### 2.2 在架构中的位置

```text
Worker (scheduler/agents)
  │
  ├── ExecutorPort (application/ports/)  ← 接口定义在应用层
  │
  └── ExecutorClient (infrastructure/clients/)
        │
        └── HTTP → Executor (apps/executor/)
                      │
                      ├── Docker Engine API
                      │     └── 项目隔离容器
                      │
                      ├── policies/     ← 命令白名单、路径策略、网络策略
                      ├── runtime/      ← 容器生命周期封装
                      └── security/     ← 路径校验、命令参数校验
```

### 2.3 涉及的数据库表

| 表 | 角色 |
| --- | --- |
| `project_runtimes` | 运行实例记录：容器状态、环境快照、逻辑目录键 |
| `resource_usages` | CPU、内存、Token 采样数据 |
| `runtime_logs` | 容器和命令执行日志 |
| `file_artifacts` | 报告、证据等文件的逻辑键和元数据 |

**注意：** `runtimes` 模块本身没有直接的 REST API 接口暴露给浏览器。运行实例信息通过 `ProjectDetail.runtime` 字段返回。

## 3. 领域模型

### 3.1 运行实例实体

```text
ProjectRuntime
├── id: UUID
├── project_id: UUID                        # 唯一约束，MVP 每项目最多一个
├── runtime_identifier: str?                # 执行网关环境编号，如 "asa-{project}-001"
├── container_status: ContainerStatus       # 生命周期状态
├── workspace_key: str?                     # 工作目录逻辑键
├── repository_key: str?                    # 源码目录逻辑键
├── environment_snapshot: dict              # 不含密钥的环境快照
├── started_at: datetime?
├── stopped_at: datetime?
├── destroyed_at: datetime?
├── error_message: str?                     # 脱敏错误摘要
├── created_at: datetime
└── updated_at: datetime
```

### 3.2 容器状态机

```text
pending → starting → running → stopping → stopped
                                      ↘ destroyed
                                      ↘ failed
```

| 状态 | 说明 |
| --- | --- |
| `pending` | 已创建运行记录，容器尚未开始创建 |
| `starting` | Docker 容器创建中（拉取镜像、创建网络、挂载卷） |
| `running` | 容器正常运行，可接受文件/命令请求 |
| `stopping` | 收到停止信号，容器正在收敛 |
| `stopped` | 容器已停止但未销毁（按配置可能保留） |
| `destroyed` | 容器已完全销毁 |
| `failed` | 容器创建或运行中发生不可恢复错误 |

### 3.3 业务规则

| 规则 | 说明 |
| --- | --- |
| 每项目最多一个运行实例 | `project_runtimes.project_id` UNIQUE 约束 |
| 容器非 root 用户运行 | Dockerfile 指定 USER，禁止 `user: root` |
| 只读根文件系统 | `read_only: true`，仅 workspace 可写 |
| 源码只读挂载 | `repositories/{project_id}/` 以 `:ro` 挂载 |
| 禁止挂载 Docker Socket | 不容许 `/var/run/docker.sock` 出现在任何挂载 |
| 禁止挂载宿主机系统目录 | 不容许 `/etc`、`/proc`、`/sys`、`/root` 等路径 |
| 默认禁止外网 | 容器网络默认隔离；需下载依赖时按阶段策略和域名白名单临时开放 |
| 资源限制 | CPU、内存、磁盘、进程数上限由配置指定 |

### 3.4 领域异常

| 异常 | 说明 |
| --- | --- |
| `RuntimeNotFound` | 运行实例不存在 |
| `ContainerCreateFailed` | 容器创建失败 |
| `ContainerStartFailed` | 容器启动失败 |
| `ContainerTimeoutExceeded` | 命令或容器操作超时 |
| `PathTraversalBlocked` | 路径穿越被拦截 |
| `CommandPolicyDenied` | 命令不在白名单中 |
| `ResourceLimitExceeded` | CPU/内存/磁盘/进程数超限 |
| `NetworkPolicyDenied` | 外网访问被策略拒绝 |

## 4. Executor 内部协议

### 4.1 接口定义

Executor 只监听内部网络，提供以下预定义操作（不接受任意 Docker API 调用）：

| 操作 | 说明 |
| --- | --- |
| `create_container` | 按项目配置创建容器，挂载目录，设置资源限制 |
| `start_container` | 启动已创建的容器 |
| `stop_container` | 先发 SIGTERM，宽限期后 SIGKILL |
| `destroy_container` | 停止并删除容器及相关资源 |
| `get_container_status` | 查询容器当前状态和资源使用 |
| `read_file` | 读取项目容器内文件（受限于项目根目录） |
| `list_directory` | 遍历项目容器内目录 |
| `search_content` | 在项目文件内搜索关键字 |
| `execute_command` | 执行受控命令（程序名+参数数组） |
| `health_check` | Executor 自身健康状态 |

### 4.2 请求格式

Worker 调用必须携带：

```text
{
  "request_id": "uuid",        # 链路标识
  "project_id": "uuid",        # 项目标识
  "runtime_id": "uuid",        # 运行实例标识
  "service_token": "string",   # 内部服务认证
  "schema_version": "1.0",     # 协议版本
  "operation": "execute_command",
  "parameters": { ... }        # 操作参数
}
```

### 4.3 响应格式

```text
{
  "request_id": "uuid",
  "status": "success" | "error",
  "data": { ... },
  "error": {
    "code": "COMMAND_POLICY_DENIED",
    "message": "command not in whitelist"
  }
}
```

## 5. 路径安全

### 5.1 路径规范化

所有文件操作在 Executor 端执行以下校验链：

```text
用户输入路径
  ├── 1. 拒绝绝对路径（以 / 开头）
  ├── 2. 拒绝空字节和路径编码绕过
  ├── 3. 规范化路径（解析 . 和 .. 段）
  ├── 4. 基于项目根目录拼接完整路径
  ├── 5. 解析符号链接
  ├── 6. os.path.realpath() 获取真实路径
  ├── 7. 确认真实路径位于允许根目录内
  └── 8. 放行或拒绝
```

### 5.2 逻辑目录结构

```text
数据卷根目录/
├── repositories/{project_id}/     ← 拉取后源码，只读挂载
├── workspace/{project_id}/        ← 中间文件，可读写
├── runtime_logs/{project_id}/     ← 归档日志
└── reports/{project_id}/          ← 报告文件
```

- 业务代码只使用 `ArtifactStorage` 逻辑键，不拼接宿主机绝对路径。
- 逻辑键不得以 `/` 开头，不得包含独立 `..` 路径段。
- 用户输入绝不直接拼接到 `runtime_logs/`、`reports/`、`workspace/`、`repositories/` 的宿主机根路径。

## 6. 命令安全

### 6.1 命令格式

```text
正确（参数数组，不拼接 Shell）：
  ["python", "-c", "import sys; print(sys.version)"]

错误（Shell 字符串）：
  "python -c 'import sys; print(sys.version)'"
```

### 6.2 命令策略校验

每条命令必须通过 `CommandPolicy` 校验：

```text
CommandPolicy.check(program, args, workdir, env, timeout)
  │
  ├── 1. program 在允许白名单中？
  │     白名单示例：python, node, npm, pip, git, curl, grep, find, ...
  ├── 2. args 不包含 Shell 元字符（; | & $ ` ( ) { } < >）？
  ├── 3. workdir 在项目根目录内？
  ├── 4. env 不覆盖关键变量（PATH, LD_PRELOAD, HOME）？
  ├── 5. timeout 不超过配置上限？
  └── 6. 全部通过 → 放行 | 任一失败 → 拒绝 + 审计
```

### 6.3 容器安全基线

```text
容器安全配置（Docker 层面）：
  ├── User: 非 root (uid != 0)
  ├── ReadOnlyRootFilesystem: true
  ├── NoNewPrivileges: true
  ├── Seccomp: 默认 profile + 项目特定规则
  ├── CapDrop: ALL
  ├── CapAdd: 仅必要项（如 NET_BIND_SERVICE）
  ├── 资源限制：
  │     ├── CPU: --cpus (如 2.0)
  │     ├── Memory: --memory (如 2g)
  │     ├── Disk: --storage-opt size (如 10g)
  │     └── PidsLimit: --pids-limit (如 100)
  ├── Network: 默认 none，需要时临时开放
  └── 挂载：
        ├── repositories/{id}/ → /app/source:ro
        └── workspace/{id}/ → /app/workspace:rw
```

## 7. 资源采样

`operations_assistant` 角色通过 Executor 采集容器资源使用情况：

```text
采样数据 → resource_usages 表
  ├── cpu_usage: numeric(9,3)    ← 百分值，多核可超过 100
  ├── memory_usage: bigint       ← 字节
  ├── token_count: bigint        ← 采样时累计 token 数
  └── recorded_at: timestamptz   ← 采样时间

采样策略：
  ├── 固定周期（如每 30 秒）
  ├── 批量写入 PostgreSQL（如每 10 条或每 5 分钟）
  └── 前端降采样展示（按时间窗口聚合）
```

## 8. 代码实现指南

### 8.1 目录结构

```text
packages/backend-core/src/asa_core/domain/runtimes/
├── entities.py              # ProjectRuntime 聚合根
├── container_status.py      # ContainerStatus 枚举和状态机
├── policies.py              # ContainerPolicy (共享策略接口)
├── value_objects.py         # RuntimeIdentifier, WorkspaceKey
└── exceptions.py            # 领域异常

packages/backend-core/src/asa_core/application/
├── commands/
│   ├── create_runtime.py    # CreateRuntime Handler
│   ├── start_runtime.py     # StartRuntime Handler
│   ├── stop_runtime.py      # StopRuntime Handler
│   └── destroy_runtime.py   # DestroyRuntime Handler
├── services/
│   └── resource_sampler.py  # ResourceSampler
└── ports/
    └── executor_port.py     # ExecutorPort 接口

apps/executor/src/asa_executor/
├── main.py                  # FastAPI 应用入口
├── bootstrap.py             # 依赖组装
├── api/
│   └── routes.py            # 内部 API 路由
├── schemas/
│   └── requests.py          # 内部 Pydantic Schema
├── services/
│   ├── container_service.py # Docker 操作封装
│   ├── file_service.py      # 文件操作
│   └── command_service.py   # 命令执行
├── policies/
│   ├── command_policy.py    # 命令白名单和参数校验
│   ├── path_policy.py       # 路径校验和穿越防护
│   └── network_policy.py    # 网络访问策略
├── runtime/
│   └── docker_adapter.py    # Docker SDK 封装（不向上暴露原始客户端）
└── security/
    ├── path_validator.py    # 路径规范化与校验
    └── token_auth.py        # 内部服务认证
```

### 8.2 关键实现约束

- **API 和 Worker 禁止直接访问 Docker Socket**。只有 Executor 可以调用 Docker Engine。
- **Executor 禁止直接访问业务数据库和 Redis**。
- `docker_adapter.py` 封装 Docker SDK，不向上层暴露原始 `docker.from_env()` 客户端。
- 命令使用**程序名和参数数组**，不拼接 Shell 字符串。程序、参数、工作目录、环境变量、超时和输出上限分别校验。
- 路径校验链必须在 Executor 端执行，不依赖调用方提供合法路径。
- 容器镜像使用**固定摘要**（`image@sha256:...`）而非 `latest` 标签，并执行漏洞扫描。
- 模型不能直接决定可执行程序白名单——白名单由 `policies/command_policy.py` 集中维护。

## 9. 安全要点

- 每个项目独立容器、独立工作目录、独立运行编号——**不允许复用其他项目的容器**。
- 容器进程使用**非 root 用户**、只读根文件系统、最小 Capabilities。
- 启用 `no-new-privileges`、Seccomp、进程数、CPU、内存、磁盘和超时限制。
- 默认**禁止外网**，临时开放必须匹配阶段策略和域名白名单。
- 禁止挂载宿主机 Docker Socket、密钥目录、系统目录和其他项目目录。
- 文件读取、目录遍历、搜索结果和命令输出**均有大小上限**。
- Executor 操作结果包含稳定错误码，不向 Worker 暴露 Docker SDK 原始异常。
- 日志记录策略结果、退出码和耗时，敏感参数先脱敏再写日志。
- `environment_snapshot` 不含密钥、凭证和完整环境变量。

## 10. 测试要点

### 10.1 Executor 单元测试

- 命令策略：允许/拒绝的程序、非法参数、Shell 元字符拦截
- 路径校验：合法相对路径、绝对路径拒绝、`..` 穿越拒绝、符号链接逃逸拒绝
- 路径规范化：`./foo/../bar` → `bar`
- 网络策略：默认拒绝外网、白名单域名允许
- 容器操作：创建、启动、停止、销毁流程

### 10.2 容器集成测试

- 使用专用无敏感数据测试镜像
- 不挂载宿主机真实源码和密钥目录
- 测试容器非 root 用户运行
- 测试 CPU/内存/磁盘/进程数限制生效
- 测试命令超时和输出上限
- 测试只读文件系统（写入 workspace 成功，写入源码目录失败）
- 测试符号链接逃逸被阻止
- 测试容器销毁后资源清理

### 10.3 应用层测试

- 运行实例创建和状态机迁移
- 环境快照写入和脱敏
- 资源采样数据批量写入
- Executor 不可用时的错误处理和重试

## 11. 配置项

| 配置项 | 说明 |
| --- | --- |
| 项目容器镜像 | 固定摘要，不在代码中写死 |
| 容器 CPU 上限 | `ASA_CONTAINER_CPU_LIMIT`，如 2.0 |
| 容器内存上限 | `ASA_CONTAINER_MEMORY_LIMIT`，如 2g |
| 容器磁盘上限 | `ASA_CONTAINER_DISK_LIMIT`，如 10g |
| 容器进程数上限 | `ASA_CONTAINER_PIDS_LIMIT`，如 100 |
| 命令默认超时 | `ASA_COMMAND_DEFAULT_TIMEOUT_SECONDS` |
| 命令最大输出 | `ASA_COMMAND_MAX_OUTPUT_BYTES` |
| 停止宽限期 | `ASA_CONTAINER_STOP_GRACE_PERIOD_SECONDS` |
| 外网白名单域名 | `ASA_CONTAINER_ALLOWED_DOMAINS` |
| 资源采样周期 | `ASA_RESOURCE_SAMPLE_INTERVAL_SECONDS` |
| Executor 内部认证 Token | `ASA_EXECUTOR_SERVICE_TOKEN` |

以上默认值均由部署和安全评审确认，不得在代码中写死。
