# 报告模块（reports）

## 1. 模块概述

### 1.1 定位

`reports` 模块负责将评估过程中持久化的漏洞、攻击路径和统计数据进行汇总，生成结构化的安全评估报告——包括 Markdown 正文、安全清理后的 HTML 以及可下载文件，并提供在线预览和受权下载。

### 1.2 设计依据

- `docs/1_PRD/自动化安全评估系统-PRD.md`
- `docs/3_概要设计/自动化安全评估系统-概要设计总纲.md` — 第 5.2 节、第 8.6 节
- `docs/4_开发规范/API接口文档.md` — 第 7.5-7.6 节（报告查询与下载）
- `docs/4_开发规范/后端/后端开发规范.md` — 第 13.5 节（报告）
- `docs/4_开发规范/数据库/数据库设计.md` — `reports`、`file_artifacts` 表设计

### 1.3 职责边界

| 职责 | 说明 |
| --- | --- |
| 报告生成 | 从数据库持久化快照读取漏洞、路径和统计，渲染为 Markdown |
| HTML 清理 | 将 Markdown 转 HTML 后执行允许列表清理（去脚本、事件属性、危险 URL） |
| 文件管理 | 写入 Markdown/HTML 到 `reports/{project_id}/`，记录 `file_artifacts` |
| 完整性保证 | SHA-256 摘要计算和校验 |
| 在线预览 | 返回 Markdown + 清理后 HTML 正文 |
| 受权下载 | 校验权限后返回报告文件字节流 |
| 版本管理 | 支持多版本报告（MVP 至多一个），`(project_id, version)` 唯一 |

**不负责：** 漏洞发现、攻击路径构建（vulnerabilities/attack_paths）、模板渲染的 AI 内容生成（agents/report_editor）——这些由对应模块处理。

## 2. 架构与依赖

### 2.1 报告生成流程

```text
report_generate 阶段 (agents/report_editor)
  │
  ├── 1. 从数据库读取持久化快照：
  │     ├── 项目基本信息（projects）
  │     ├── 全部漏洞（vulnerabilities，按风险等级排序）
  │     ├── 全部攻击路径（attack_paths + items + 关联漏洞）
  │     └── 统计数据（vulnerability_count、attack_path_count 等）
  │
  ├── 2. AI 角色生成结构化报告内容
  │     └── 输出通过 Pydantic Schema 校验
  │
  ├── 3. Jinja2 渲染 Markdown 模板
  │     └── 模板输入为结构化对象，不把模型自由文本当模板代码
  │
  ├── 4. Markdown-it-py 转换 HTML
  │     └── 允许列表清理器过滤脚本、事件属性、危险 URL
  │
  ├── 5. 写入文件到 reports/{project_id}/ （通过 ArtifactStorage）
  │     ├── 临时文件 → SHA-256 → 原子替换
  │     └── 写入 file_artifacts 元数据
  │
  ├── 6. 数据库保存报告记录（report_status='ready'）
  │     ├── report_markdown, report_html
  │     ├── report_file_path (逻辑键)
  │     ├── content_sha256
  │     └── 必须同时具备 Markdown、HTML、文件逻辑键和摘要
  │
  └── 7. 发送 domain_events (report_ready)
```

### 2.2 涉及的数据库表

| 表 | 角色 |
| --- | --- |
| `reports` | 报告主表：状态、Markdown/HTML 正文、逻辑键、摘要 |
| `file_artifacts` | 报告文件的元数据（逻辑键、SHA-256、大小、媒体类型） |
| `vulnerabilities` | 报告内容来源 |
| `attack_paths` | 报告内容来源 |
| `domain_events` | `report_ready` 事件 |

### 2.3 涉及的 API 接口

| 接口 | 方法 | URL | 说明 |
| --- | --- | --- | --- |
| 查询报告 | `GET` | `/api/v1/projects/{project_id}/report` | 查询最新或指定版本报告 |
| 下载报告 | `GET` | `/api/v1/projects/{project_id}/report/download` | 下载 Markdown 或 HTML 文件 |

## 3. 领域模型

### 3.1 报告实体

```text
Report
├── id: UUID
├── project_id: UUID
├── generated_by_task_id: UUID?
├── version: int                      # 从 1 开始，项目内唯一
├── report_status: "pending" | "generating" | "ready" | "failed"
├── report_markdown: str?             # Markdown 正文
├── report_html: str?                 # 已清理 HTML
├── report_file_path: str?            # 下载逻辑键（非宿主机绝对路径）
├── content_sha256: str?              # 报告文件 SHA-256
├── error_message: str?               # 脱敏生成失败原因
├── created_at: datetime
└── updated_at: datetime
```

### 3.2 报告状态机

```text
pending → generating → ready
                    ↘ failed
```

- `pending`：报告记录已创建，尚未开始生成。
- `generating`：report_editor 正在生成报告内容。
- `ready`：报告已生成并落盘，Markdown、HTML、文件逻辑键和 SHA-256 齐全。
- `failed`：生成失败，`error_message` 记录脱敏原因。已保存的漏洞和攻击路径不受影响。

### 3.3 业务规则

| 规则 | 说明 |
| --- | --- |
| 版本项目内唯一 | `(project_id, version)` UNIQUE |
| `ready` 状态必须字段齐全 | Markdown + HTML + 文件逻辑键 + SHA-256 |
| `failed` 状态必须有错误 | `error_message` 非空 |
| 报告失败不删除漏洞和路径 | 已保存的评估结果继续可查 |
| 模板固定 | 不接受用户上传模板 |
| `report_file_path` 是逻辑键 | 不允许包含绝对路径和 `..` |
| `report_html` 必须安全清理 | 不允许脚本、事件属性、危险 URL |

### 3.4 领域异常

| 异常 | HTTP 状态 | 业务码 |
| --- | --- | --- |
| `ReportNotFound` | 404 | `REPORT_NOT_FOUND` |
| `ReportNotReady` | 409 | `REPORT_NOT_READY` |
| `ReportFileNotFound` | 404 | `REPORT_FILE_NOT_FOUND` |
| `ReportIntegrityError` | 500 | `REPORT_INTEGRITY_ERROR` |

## 4. HTML 安全清理

### 4.1 清理规则

```text
Markdown-it-py 渲染输出
  │
  └── HTML Cleaner (允许列表模式)
        │
        ├── 允许的标签：
        │     h1-h6, p, ul, ol, li, blockquote, pre, code,
        │     strong, em, a, table, thead, tbody, tr, th, td, br, hr
        │
        ├── 允许的属性：
        │     a: href (仅 http/https/mailto)
        │     code: class (仅 language-*)
        │     th/td: align
        │
        ├── 禁止的内容：
        │     script, style, iframe, object, embed, link
        │     on* 事件属性 (onclick, onerror, ...)
        │     javascript: data: vbscript: URL
        │
        └── 输出：安全 HTML 字符串
```

### 4.2 实现方式

使用 `bleach` 或类似库的允许列表模式。清理规则集中配置，不在多处复制。

## 5. 查询与下载实现

### 5.1 报告查询

```text
GET /api/v1/projects/{project_id}/report?version=1

流程：
  ├── 1. 校验项目存在 + 用户权限
  ├── 2. 查询 reports WHERE project_id=:pid [AND version=:ver]
  │     └── 不指定版本时取最新 (ORDER BY version DESC LIMIT 1)
  ├── 3. 报告不存在：
  │     └── 项目尚未进入 report_generate 阶段 → 404 REPORT_NOT_FOUND
  └── 4. 返回统一 JSON 响应
        ├── ready: 返回完整 report_markdown + report_html
        ├── generating: 返回 null 正文
        └── failed: 返回 error_message

注意：generating 和 failed 状态仍返回 200（查询成功），
     只有报告记录本身不存在才返回 404。
```

### 5.2 报告下载

```text
GET /api/v1/projects/{project_id}/report/download?version=1&format=markdown

流程：
  ├── 1. 校验 Cookie 会话 + 项目权限
  ├── 2. 查询报告记录，校验 report_status='ready'
  │     └── 非 ready → 409 REPORT_NOT_READY
  ├── 3. 通过 ArtifactStorage 读取文件（使用 report_file_path 逻辑键）
  │     └── 文件不存在 → 404 REPORT_FILE_NOT_FOUND
  ├── 4. 校验文件 SHA-256 与 content_sha256 一致
  │     └── 不一致 → 500 REPORT_INTEGRITY_ERROR + 审计
  ├── 5. 规范化文件名：asa-report-{project_id}-v{version}.{ext}
  └── 6. 返回文件字节流（非 JSON 包装）

响应头：
  Content-Type: text/markdown; charset=utf-8 (或 text/html)
  Content-Disposition: attachment; filename="asa-report-xxx-v1.md"
  Content-Length: <size>
  Digest: sha-256=<base64>
  Cache-Control: no-store (或带权限校验的强 ETag)

注意：
  - 每次下载必须重新校验权限，不提供永久公开 URL。
  - 文件名经过安全规范化，禁止响应头注入。
  - 服务端读取的是逻辑键，不接受客户端传入文件路径。
```

## 6. 代码实现指南

### 6.1 目录结构

```text
packages/backend-core/src/asa_core/domain/reports/
├── entities.py              # Report 聚合根
├── value_objects.py         # ReportVersion, ContentSha256
├── html_cleaner.py          # HTML 安全清理（允许列表模式）
└── exceptions.py            # ReportNotFound, ReportNotReady, ReportIntegrityError

packages/backend-core/src/asa_core/application/
├── commands/
│   └── generate_report.py   # GenerateReport Handler
├── queries/
│   ├── get_report.py        # GetReport Query
│   └── download_report.py   # DownloadReport Query
└── ports/
    ├── report_repository.py
    └── artifact_storage.py  # ArtifactStorage Port

apps/worker/src/asa_worker/reporting/
├── report_builder.py        # 从数据库读取快照，调用 AI 生成内容
├── markdown_renderer.py     # Jinja2 模板渲染
└── html_converter.py        # Markdown-it-py 转换 + 清理

apps/api/src/asa_api/routers/v1/reports.py
apps/api/src/asa_api/schemas/reports.py
```

### 6.2 关键实现约束

- **报告从数据库持久化快照生成**，不依赖前端状态和临时聊天上下文。
- **Jinja2 模板输入为结构化对象**，不把模型自由文本当作模板代码或直接拼接到模板字符串。
- **Markdown 转 HTML 后必须执行允许列表清理**，过滤脚本、事件属性和危险 URL。
- **文件写入采用临时文件 + SHA-256 + 原子替换**，避免读取到半成品文件。
- **文件成功落盘并校验后才能将报告置为 `ready`**。
- 报告失败不得删除已保存的漏洞和攻击路径。
- `report_file_path` 通过 `ArtifactStorage` 逻辑键解析，不拼接宿主机路径。

## 7. 安全要点

- 报告下载**每次必须重新校验项目权限**，不提供永久公开 URL。
- 下载文件名执行**字符白名单**处理，防止响应头注入（如文件名中含 `\r\n`）。
- `report_html` 必须由后端执行 HTML 清理后返回——前端不自行清理后再渲染。
- Markdown 正文（`report_markdown`）也按不可信文本处理，前端渲染前执行安全转义。
- 报告不暴露 `report_file_path` 逻辑键给外部 API 响应。
- 内部字段（如宿主机绝对路径解析结果）不出现在下载响应中。

## 8. 测试要点

### 8.1 单元测试

- HTML 清理器：允许的标签和属性放行、script/style/事件属性/危险 URL 移除
- 报告状态机：pending → generating → ready/failed
- SHA-256 摘要计算和校验
- 文件名规范化（去除路径分隔符、危险字符）

### 8.2 API 测试

- `GET /api/v1/projects/{project_id}/report` — ready 状态返回完整正文、generating 状态返回 null 正文、报告不存在（404）
- `GET /api/v1/projects/{project_id}/report/download` — 成功（200 + 正确的 Content-Type + Content-Disposition）、报告未就绪（409 `REPORT_NOT_READY`）、文件缺失（404 `REPORT_FILE_NOT_FOUND`）、摘要不匹配（500 `REPORT_INTEGRITY_ERROR`）
- 未登录拒绝下载（401）
- 无项目权限拒绝下载（403）
- 下载响应不包含 JSON 包装

### 8.3 集成测试

- 完整生成流程：数据快照 → Jinja2 渲染 → HTML 转换清理 → 文件写入 → 数据库更新
- HTML 清理器对抗性测试（XSS payload、javascript: URL、事件属性注入）
- 原子写入不产生半文件
- 文件摘要不匹配时报告不置为 ready
- 报告失败后漏洞和攻击路径仍可查询
