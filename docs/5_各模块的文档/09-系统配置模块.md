# 系统配置模块（config）

## 1. 模块概述

### 1.1 定位

`config` 模块负责管理 ASA 系统的运行时参数——包括项目默认超时、最大并发数、日志/文件保留天数、启用环境类型列表和扩展设置。配置采用**不可变版本追加**模式，每次更新创建新版本并激活，旧版本保留为历史记录。

### 1.2 设计依据

- `docs/1_PRD/自动化安全评估系统-PRD.md`
- `docs/3_概要设计/自动化安全评估系统-概要设计总纲.md` — 第 5.2 节
- `docs/4_开发规范/API接口文档.md` — 第 4.5-4.6 节（查询/更新系统配置）
- `docs/4_开发规范/后端/后端开发规范.md` — 第 6 章（配置与应用启动）
- `docs/4_开发规范/数据库/数据库设计.md` — `system_configs` 表设计

### 1.3 职责边界

| 职责 | 说明 |
| --- | --- |
| 配置查询 | 返回当前生效配置（管理员专属） |
| 配置更新 | 以不可变版本创建并激活新配置，使用乐观锁防并发冲突 |
| 版本管理 | 每次更新生成新版本号，保留完整历史 |
| 唯一生效 | 部分唯一索引保证最多一个 `is_active=true` 记录 |
| 运行时快照 | 项目启动时读取生效配置快照，运行中项目不受后续配置变更影响 |

**不负责：** 应用进程自身的环境变量配置（如数据库连接字符串、Redis 地址）——这些由 `bootstrap.py` 从环境变量加载，不通过本模块管理。

## 2. 架构与依赖

### 2.1 涉及的数据库表

| 表 | 角色 |
| --- | --- |
| `system_configs` | 配置版本主表：不可变版本、部分唯一生效索引 |
| `audit_logs` | 配置更新审计 |

### 2.2 涉及的 API 接口

| 接口 | 方法 | URL | 认证 |
| --- | --- | --- | --- |
| 查询系统配置 | `GET` | `/api/v1/system/config` | Cookie，仅 `admin` |
| 更新系统配置 | `PUT` | `/api/v1/system/config` | Cookie + CSRF，仅 `admin` |

## 3. 领域模型

### 3.1 配置实体

```text
SystemConfig
├── id: UUID
├── version: int                          # 单调递增，从 1 开始
├── default_timeout_seconds: int?         # 默认超时（秒），null=未配置
├── max_concurrent_projects: int?         # 最大并发项目数
├── log_retention_days: int?              # 日志保留天数
├── file_retention_days: int?             # 文件保留天数
├── enabled_environment_types: str[]      # 启用环境类型列表，不得重复
├── settings: dict                        # 非敏感扩展配置（JSON 对象，白名单过滤）
├── is_active: bool                       # 是否生效
├── updated_by: UUID                      # 操作管理员
├── created_at: datetime
└── updated_at: datetime
```

### 3.2 业务规则

| 规则 | 说明 | 实现 |
| --- | --- | --- |
| 版本号单调递增 | 每次更新 version = 当前最大 + 1 | 应用层生成 |
| 最多一个生效版本 | 同一时刻 `is_active=true` 的记录 ≤ 1 | 部分唯一索引 `uq_system_configs__one_active` |
| 乐观锁版本控制 | 更新时传入 `expected_version`，与当前生效版本不一致时拒绝 | 应用层校验 |
| 不可变历史 | 已有版本不修改，只创建新版本 | 只 INSERT 不 UPDATE 已有配置的业务字段 |
| 未确认值保持 NULL | 不在初始化 SQL 中猜测生产值 | 启动时不插入预置配置 |
| settings 白名单过滤 | 拒绝密钥、Token、凭证类字段 | 递归敏感键过滤 |
| 新配置只影响后续项目 | 运行中项目使用启动时快照 | 配置读取发生在项目启动事务内 |
| 仅管理员可操作 | 普通用户访问返回 `ADMIN_REQUIRED` | 依赖注入 |

### 3.3 领域异常

| 异常 | HTTP 状态 | 业务码 |
| --- | --- | --- |
| `SystemConfigNotFound` | 404 | `SYSTEM_CONFIG_NOT_FOUND` |
| `ConfigVersionConflict` | 409 | `CONFIG_VERSION_CONFLICT` |
| `AdminRequired` | 403 | `ADMIN_REQUIRED` |

## 4. 核心流程

### 4.1 查询配置

```text
GET /api/v1/system/config
  │
  ├── 1. 校验当前用户 role='admin'
  └── 2. 查询 system_configs WHERE is_active=true
        ├── 存在 → 返回 200
        └── 不存在 → 404 SYSTEM_CONFIG_NOT_FOUND

注意：
  - settings 只返回允许前端展示的非敏感配置。
  - 密钥、Token、证书、仓库凭证、容器内部细节不得通过该接口返回。
```

### 4.2 更新配置

```text
PUT /api/v1/system/config
  │
  ├── 1. 校验 CSRF Token + role='admin'
  ├── 2. 校验请求体：
  │     ├── expected_version: integer|null
  │     │     └── 非 null 时必须匹配当前生效版本
  │     ├── 各数值字段: 正数或 null
  │     ├── enabled_environment_types: 字符串数组，无重复
  │     └── settings: JSON 对象 → 白名单 + 敏感键过滤
  │
  ├── 3. 事务开始：
  │     ├── 锁定当前生效配置（如有）
  │     ├── 校验 expected_version：
  │     │     ├── null → 首次创建配置
  │     │     └── 等于当前生效版本 → 允许更新
  │     │     └── 不等于 → 409 CONFIG_VERSION_CONFLICT
  │     ├── 将旧生效配置 is_active = false
  │     ├── INSERT 新版本 (version = 旧版本 + 1 或 1, is_active = true)
  │     ├── 写入 audit_logs
  │     └── 提交事务
  │
  └── 4. 返回 200 + 新配置

配置切换原子性保证：
  ┌─────────────────────────────────────────┐
  │ 同一事务内：                              │
  │   1. 旧记录 is_active = false            │
  │   2. 新记录 INSERT (is_active = true)     │
  │   3. 部分唯一索引阻止中间态出现双活       │
  └─────────────────────────────────────────┘
```

### 4.3 运行时配置读取

项目启动时（Worker 端）读取生效配置快照：

```text
启动事务内：
  ├── 读取 system_configs WHERE is_active=true
  ├── 快照 max_concurrent_projects → 用于并发检查
  ├── 快照 default_timeout_seconds → 用于容器超时
  └── 快照写入 project_runtimes.environment_snapshot

运行中项目不受后续配置变更影响。
```

## 5. 数据库设计要点

### 5.1 部分唯一索引

```sql
CREATE UNIQUE INDEX uq_system_configs__one_active
  ON system_configs (is_active)
  WHERE is_active = true;
```

这个索引保证整个表中只有一行 `is_active=true`，是数据库层防止双活配置的核心机制。

### 5.2 JSONB 安全

`settings` 字段的写入规则：
- 顶层必须是 JSON 对象（`jsonb_typeof(settings) = 'object'`）。
- 写入前执行字段白名单过滤：只保留已知的安全配置键。
- 递归过滤敏感键：拒绝含 `key`、`secret`、`token`、`password`、`credential` 的键路径。
- 大小限制：如 64KB。

## 6. 代码实现指南

### 6.1 目录结构

```text
packages/backend-core/src/asa_core/domain/config/
├── entities.py              # SystemConfig 聚合根
├── value_objects.py         # EnvironmentType, ConfigVersion
├── settings_filter.py       # Settings 白名单和敏感键过滤
└── exceptions.py            # SystemConfigNotFound, ConfigVersionConflict

packages/backend-core/src/asa_core/application/
├── commands/
│   └── update_config.py     # UpdateConfig Handler (含乐观锁逻辑)
├── queries/
│   └── get_config.py        # GetConfig Query
└── ports/
    └── config_repository.py

apps/api/src/asa_api/routers/v1/config.py
apps/api/src/asa_api/schemas/config.py
```

### 6.2 关键实现约束

- **事务内切换版本**：取消旧版本和激活新版本在同一事务，部分唯一索引阻止双活。
- **乐观锁由应用层校验**：比较 `expected_version` 与数据库当前生效版本，不匹配返回 `CONFIG_VERSION_CONFLICT`。
- **version 递增在应用层生成**：`MAX(version) + 1` 在事务内执行。
- **`settings` 使用递归白名单过滤**：不接受任意 JSON，只保留预定义的安全配置键。
- **环境变量（`ASA_*`）不进入 `system_configs`**：应用进程配置（数据库连接串等）与系统业务配置分离。
- 初始化 SQL 不写入猜测配置——未确认的超时、并发和保留周期保持 `NULL`。

## 7. 安全要点

- 仅管理员角色可访问配置接口（`role='admin'`）。
- `settings` JSON 写入前执行白名单过滤和敏感键递归检测。
- 配置响应不返回密钥、Token、证书、仓库凭证、容器内部细节。
- 配置更新写入审计日志。
- `updated_by` 记录操作管理员，外键 `RESTRICT` 阻止删除仍拥有配置版本的用户。

## 8. 测试要点

### 8.1 单元测试

- 乐观锁：`expected_version` 匹配/不匹配当前生效版本
- Settings 白名单过滤：合法键保留、敏感键移除、非白名单键移除
- 版本号生成：首次创建 version=1，后续递增
- 数值校验：正数、null 允许

### 8.2 API 测试

- `GET /api/v1/system/config` — 管理员查询成功（200）、普通用户拒绝（403 `ADMIN_REQUIRED`）、尚无配置（404）
- `PUT /api/v1/system/config` — 首次创建成功（200）、正常更新成功（200）、版本冲突（409 `CONFIG_VERSION_CONFLICT`）、字段校验（422）
- 更新后 `GET` 返回新版本

### 8.3 数据库集成测试

- 部分唯一索引：同一事务内切换不会出现双活；并发插入两条 `is_active=true` → 数据库拒绝
- 版本号递增正确
- 项目启动时读取生效配置快照
