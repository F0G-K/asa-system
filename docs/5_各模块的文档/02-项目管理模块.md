# 项目管理模块（projects）

## 1. 模块概述

### 1.1 定位

`projects` 模块是 ASA 系统的核心业务模块，负责安全评估项目的全生命周期管理——从创建登记、源码接入、启动执行到停止收敛和最终删除。

### 1.2 设计依据

- `docs/1_PRD/自动化安全评估系统-PRD.md`
- `docs/3_概要设计/自动化安全评估系统-概要设计总纲.md` — 第 5.2 节、第 7.1 节、第 8.2-8.7 节
- `docs/4_开发规范/API接口文档.md` — 第 5 章（项目管理接口）
- `docs/4_开发规范/后端/后端开发规范.md` — 第 9 章（领域模型与状态机）、第 10 章（数据访问与事务）
- `docs/4_开发规范/数据库/数据库设计.md` — `projects` 表设计

### 1.3 职责边界

| 职责 | 说明 |
| --- | --- |
| 项目创建 | 登记源码来源（本地/仓库）、任务范围、隔离环境类型，创建 `created` 状态项目 |
| 项目列表 | 分页查询当前用户项目，支持状态、源码类型、关键词筛选和排序 |
| 项目详情 | 返回项目基本信息、运行环境摘要、统计值和报告状态 |
| 项目启动 | 受理 `created` 项目的异步启动，校验状态、权限和并发上限 |
| 项目停止 | 对 `running` 项目发出协作取消请求，写入 `stop_requested_at` |
| 项目删除 | 受理非运行项目的删除，执行容器销毁、文件清理和业务数据级联删除 |
| 状态机控制 | 管理 `created → running → completed/failed/stopped` 的状态迁移 |
| 源码校验 | 校验本地路径范围、仓库地址格式和凭证安全 |

**不负责：** 阶段调度、容器创建、AI 角色执行、报告生成、文件物理清理——这些分别由 `scheduler`、`runtimes`、`agents`、`reports` 和 `cleanup` 模块处理。

## 2. 架构与依赖

### 2.1 在架构中的位置

```text
浏览器 → Nginx → FastAPI API (routers/v1/projects)
                      │
                      ├── 领域层 (domain/projects/)
                      │     ├── Project (聚合根)
                      │     ├── ProjectStatusMachine (状态迁移策略)
                      │     └── SourcePathValidator (路径/仓库校验)
                      │
                      ├── 应用层 (application/)
                      │     ├── commands/CreateProject
                      │     ├── commands/StartProject
                      │     ├── commands/StopProject
                      │     ├── commands/DeleteProject
                      │     └── queries/ListProjects, GetProjectDetail
                      │
                      └── 基础设施层 (infrastructure/database/)
                            └── ProjectRepository
```

### 2.2 依赖方向

- `domain/projects` 不依赖框架、ORM、Celery 或 Docker。
- `application` 通过 Port 依赖 `ProjectRepository`、`RuntimeService`（启动时调用）、`CleanupService`（删除时调用）。
- `infrastructure` 实现 Port，不决定状态流转。
- Router 只解析请求、调用应用用例、返回统一响应。

### 2.3 涉及的数据库表

| 表 | 角色 |
| --- | --- |
| `projects` | 项目主表：名称、源码、状态、环境类型 |
| `project_runtimes` | 运行实例（启动时创建，唯一约束阻止原地重跑） |
| `runtime_stages` | 5 个固定阶段（启动时同事务创建） |
| `worker_tasks` | 首个环境准备任务（启动时同事务创建） |
| `domain_events` | Outbox 事件（状态变更 + 启动/停止/删除受理） |
| `audit_logs` | 操作审计 |

### 2.4 涉及的 API 接口

| 接口 | 方法 | URL | 认证 |
| --- | --- | --- | --- |
| 创建项目 | `POST` | `/api/v1/projects` | Cookie + CSRF |
| 查询项目列表 | `GET` | `/api/v1/projects` | Cookie |
| 查询项目详情 | `GET` | `/api/v1/projects/{project_id}` | Cookie + 项目权限 |
| 启动项目 | `POST` | `/api/v1/projects/{project_id}/start` | Cookie + CSRF + 幂等键 |
| 停止项目 | `POST` | `/api/v1/projects/{project_id}/stop` | Cookie + CSRF + 幂等键 |
| 删除项目 | `DELETE` | `/api/v1/projects/{project_id}` | Cookie + CSRF + 幂等键 |

## 3. 领域模型

### 3.1 项目聚合根

```text
Project
├── id: UUID                          # 项目标识
├── project_name: str                 # 1-128 字符
├── source_type: "local" | "repository"
├── source_path: str                  # 相对路径或脱敏仓库地址
├── task_content: str                 # 评估任务说明
├── environment_type: str             # 管理员启用的环境类型
├── project_status: ProjectStatus     # 状态
├── created_by: UUID                  # 创建者
├── stop_requested_at: datetime?      # 项目级取消标记
├── created_at: datetime
└── updated_at: datetime
```

### 3.2 项目状态机

```text
                    ┌──────────┐
                    │ created  │
                    └────┬─────┘
                         │
              ┌──────────┼──────────┐
              │ 启动成功  │          │ 源码/环境准备失败
              ▼          │          ▼
         ┌─────────┐    │     ┌────────┐
         │ running │    │     │ failed │
         └────┬────┘    │     └────────┘
              │          │
      ┌───────┼───────┐  │
      │       │       │  │
      ▼       ▼       ▼  │
  ┌───────┐┌──────┐┌──────┐
  │completed││failed││stopped│
  └───────┘└──────┘└──────┘
```

状态值：`created`、`running`、`completed`、`failed`、`stopped`。

### 3.3 业务规则

| 规则 | 实现位置 | 检查条件 |
| --- | --- | --- |
| 只有 `created` 可以启动 | 领域状态机 | `project_status == 'created'` |
| 只有 `running` 可以停止 | 领域状态机 | `project_status == 'running'` |
| `running` 项目不可删除 | 领域状态机 | `project_status != 'running'` |
| 终态不可回到 `created` | 领域状态机 | 无允许的迁移 |
| MVP 不支持原地重跑 | `project_runtimes.project_id` UNIQUE 约束 | 数据库层阻止 |
| 同一项目最多一个运行实例 | `project_runtimes.project_id` UNIQUE 约束 | 数据库层阻止 |
| 达到并发上限拒绝启动 | 应用层 | 计数 `project_status='running'` 的行数 |
| 删除需确认项目名称 | 应用层 | `confirm_project_name` 与当前值完全一致 |
| 源码地址不含内联凭证 | `SourcePathValidator` | 拒绝含 `user:password@` 的 URL |
| 环境类型必须已启用 | 应用层 | 读取生效 `system_configs.enabled_environment_types` |
| 本地路径必须在授权根目录内 | `SourcePathValidator` | 规范化路径 + 前缀校验 |

### 3.4 领域异常

| 异常 | HTTP 状态 | 业务码 |
| --- | --- | --- |
| `ProjectNotFound` | 404 | `PROJECT_NOT_FOUND` |
| `ProjectAccessDenied` | 403 | `PROJECT_ACCESS_DENIED` |
| `ProjectStatusConflict` | 409 | `PROJECT_STATUS_CONFLICT` |
| `ProjectNotRunning` | 409 | `PROJECT_NOT_RUNNING` |
| `ProjectCapacityExceeded` | 409 | `PROJECT_CAPACITY_EXCEEDED` |
| `ProjectDeleteForbidden` | 409 | `PROJECT_DELETE_FORBIDDEN` |
| `ProjectNameConfirmationMismatch` | 409 | `PROJECT_NAME_CONFIRMATION_MISMATCH` |
| `SourcePathInvalid` | 422 | `SOURCE_PATH_INVALID` |
| `SourceCredentialForbidden` | 422 | `SOURCE_CREDENTIAL_FORBIDDEN` |
| `SourceInaccessible` | 409 | `SOURCE_INACCESSIBLE` |
| `EnvironmentTypeDisabled` | 409 | `ENVIRONMENT_TYPE_DISABLED` |

## 4. 核心流程

### 4.1 项目创建

```text
POST /api/v1/projects
  │
  ├── 1. 校验 CSRF Token
  ├── 2. 校验请求体字段
  │     ├── project_name: 1-128 字符，非空
  │     ├── source_type: "local" 或 "repository"
  │     ├── source_path: 格式校验（local 为相对路径，repository 无内联凭证）
  │     ├── task_content: 非空
  │     └── environment_type: 属于当前启用环境类型列表
  ├── 3. SourcePathValidator 校验
  │     ├── local: 规范化路径，确认在授权根目录内
  │     └── repository: 不含 user:password@、不含敏感查询参数
  ├── 4. 创建 Project 聚合（project_status='created'）
  ├── 5. 持久化到 projects 表
  ├── 6. 写入审计日志
  └── 7. 返回 201 Created + ProjectDetail

注意：创建不拉取仓库、不创建容器。源码可访问性在启动时再次校验。
```

### 4.2 项目启动

```text
POST /api/v1/projects/{project_id}/start
  │
  ├── 1. 校验 CSRF Token、Idempotency-Key
  ├── 2. 校验项目存在且当前用户有权限
  ├── 3. 幂等检查（同一 Key 重复请求返回首次受理结果）
  ├── 4. 获取项目级 advisory lock
  ├── 5. 事务开始：
  │     ├── 条件更新检查 project_status='created'
  │     ├── 检查并发上限（COUNT running 项目 < max_concurrent_projects）
  │     ├── 创建 project_runtimes (container_status='pending')
  │     ├── 创建 5 条 runtime_stages (stage_status='idle')
  │     ├── 创建首个 worker_tasks（environment_scan 阶段）
  │     ├── 写入幂等记录
  │     ├── 写入 domain_events (project_status 变更)
  │     └── 提交事务
  ├── 6. 释放项目锁
  ├── 7. 投递 Celery 任务（在事务外）
  └── 8. 返回 202 Accepted

注意：
- API 不等待仓库拉取、容器创建或阶段执行。
- 源码准备成功后项目转 running，准备失败转 failed。
- 事务内创建运行记录+阶段+任务+Outbox，事务外投递 Celery。
```

### 4.3 项目停止

```text
POST /api/v1/projects/{project_id}/stop
  │
  ├── 1. 校验 CSRF Token、Idempotency-Key
  ├── 2. 校验项目存在且当前用户有权限
  ├── 3. 幂等检查
  ├── 4. 事务开始：
  │     ├── 条件更新检查 project_status='running'
  │     ├── 写入 stop_requested_at
  │     ├── 写入取消信号（Redis）
  │     ├── 写入 domain_events (stop_requested)
  │     └── 提交事务
  └── 5. 返回 202 Accepted

注意：
- 受理后只标记取消意图，项目最终由 Worker 收敛为 stopped。
- 已保存的漏洞、日志、资源和报告草案继续保留。
- 阶段和任务不增加 "stopped" 状态。
```

### 4.4 项目删除

```text
DELETE /api/v1/projects/{project_id}
  │
  ├── 1. 校验 CSRF Token、Idempotency-Key
  ├── 2. 校验项目存在且当前用户有权限
  ├── 3. 幂等检查
  ├── 4. 事务开始：
  │     ├── 条件更新检查 project_status != 'running'
  │     ├── 校验 confirm_project_name 与 project_name 完全一致
  │     ├── 写入幂等记录和删除受理事件
  │     └── 提交事务
  ├── 5. 投递清理任务（Celery）
  └── 6. 返回 202 Accepted

清理任务按顺序执行（由 cleanup 模块负责）：
  1. 销毁运行容器（如有）
  2. 按 file_artifacts.logical_key 清理报告、证据、日志、工作目录
  3. 全部外部资源成功后删除 projects 行（外键级联清理业务数据）
  4. audit_logs.project_id 自动 SET NULL

部分清理失败不得删除项目行，失败项记录可诊断信息，允许同幂等键重试。
```

## 5. 查询实现

### 5.1 项目列表

```text
GET /api/v1/projects?page=1&page_size=20&project_status=running&sort=created_at:desc
  │
  ├── 1. 注入当前用户 ID
  ├── 2. 构建查询条件
  │     ├── WHERE created_by = :current_user_id    ← 数据权限
  │     ├── AND project_status = :filter (可选)
  │     ├── AND source_type = :filter (可选)
  │     └── AND project_name ILIKE '%keyword%' (可选)
  ├── 3. COUNT total
  ├── 4. SELECT 字段裁剪（不含 task_content 大文本）
  ├── 5. ORDER BY + LIMIT/OFFSET
  └── 6. 返回分页结果

索引：ix_projects__created_by_created_at
```

### 5.2 项目详情

```text
GET /api/v1/projects/{project_id}
  │
  ├── 1. 校验 project_id 为有效 UUID
  ├── 2. 查询项目（附加 created_by 权限条件）
  ├── 3. LEFT JOIN project_runtimes（最新一条）
  ├── 4. 计算统计值（从持久化数据）：
  │     ├── vulnerability_count, verified_vulnerability_count
  │     ├── attack_path_count
  │     └── worker_task_count
  ├── 5. 查询最新 report_status
  └── 6. 返回 ProjectDetail（含 runtime、statistics、report_status）

统计值从权威持久化数据计算，不依赖 WebSocket 客户端计数。
```

## 6. 代码实现指南

### 6.1 目录结构

```text
packages/backend-core/src/asa_core/domain/projects/
├── entities.py              # Project 聚合根
├── status_machine.py        # ProjectStatusMachine
├── value_objects.py         # SourcePath, EnvironmentType, ProjectName
├── validators.py            # SourcePathValidator
└── exceptions.py            # 领域异常

packages/backend-core/src/asa_core/application/
├── commands/
│   ├── create_project.py
│   ├── start_project.py
│   ├── stop_project.py
│   └── delete_project.py
├── queries/
│   ├── list_projects.py
│   └── get_project_detail.py
└── ports/
    └── project_repository.py

apps/api/src/asa_api/routers/v1/projects.py   # 项目相关 6 个路由
apps/api/src/asa_api/schemas/projects.py       # HTTP 请求/响应 Schema
```

### 6.2 关键实现约束

- **状态迁移**使用条件更新 `WHERE id=:id AND project_status=:expected`，受影响行数不等于 1 时抛出 `ProjectStatusConflict`。
- **启动事务**必须包含：项目状态检查 + 并发计数 + 创建运行记录 + 5 个阶段 + 首个任务 + 幂等记录 + Outbox 事件。
- **幂等记录**持久化到数据库（`worker_tasks.idempotency_key` 唯一约束），不依赖 Redis 或进程内缓存。
- **删除确认**必须在删除事务内再次校验项目名称，防止用户 A 删除了用户 B 确认的项目。
- **source_path**在写入数据库前脱敏，在 API 响应中再次确认不泄露凭证。
- 项目列表字段裁剪：不返回 `task_content` 大文本、`error_message` 详情。
- 项目详情中的 `statistics` 从持久化结果计算或由事务同步更新。

## 7. 并发控制

| 场景 | 策略 | 实现 |
| --- | --- | --- |
| 同一项目重复启动 | 条件更新 `project_status='created'` | 只有第一个事务成功 |
| 同一项目并发启动 | 项目级 advisory lock | 串行化启动操作 |
| 全局并发上限 | `COUNT(*) WHERE project_status='running'` | 在项目锁内执行 |
| 同一项目创建多个运行实例 | `project_runtimes.project_id` UNIQUE | 数据库拒绝 |
| 删除确认名称竞态 | 事务内校验 + 条件更新 | 防止 TOCTOU |

## 8. 安全要点

- 普通用户查询列表强制附加 `created_by = current_user_id`，Repository 层统一注入。
- 项目详情查询同步校验项目归属，不先查详情再补做权限判断。
- 删除确认名称必须在事务内与当前数据库值比较，不在应用层"先读后比"。
- `source_path` 在响应中必须为脱敏值——仓库地址已去除内联凭证，本地路径仅显示相对路径。
- 项目不存在与无权限统一返回 `PROJECT_NOT_FOUND`（404），不通过差异暴露其他用户项目信息。

## 9. 测试要点

### 9.1 单元测试

- 项目状态机全部合法和非法迁移
- 状态迁移条件更新：预期旧状态不匹配时抛异常
- SourcePathValidator：合法/非法 local 路径、合法/非法仓库 URL、内联凭证拒绝
- 项目名称格式校验（1-128 字符、空白处理）
- 环境类型在已启用列表内

### 9.2 API 测试

- `POST /api/v1/projects` — 创建成功（201）、字段校验失败（422）、内联凭证拒绝（422 `SOURCE_CREDENTIAL_FORBIDDEN`）、环境类型未启用（409）
- `GET /api/v1/projects` — 空列表、分页、状态筛选、关键词搜索、排序、普通用户只能看到自己的项目
- `GET /api/v1/projects/{id}` — 成功、项目不存在（404）、无权限（404，不区分）
- `POST /api/v1/projects/{id}/start` — 成功（202）、非 created 状态（409）、并发上限（409 `PROJECT_CAPACITY_EXCEEDED`）、幂等重试
- `POST /api/v1/projects/{id}/stop` — 成功（202）、非 running（409 `PROJECT_NOT_RUNNING`）、幂等重试
- `DELETE /api/v1/projects/{id}` — 成功（202）、运行中拒绝（409 `PROJECT_DELETE_FORBIDDEN`）、名称不匹配（409 `PROJECT_NAME_CONFIRMATION_MISMATCH`）

### 9.3 数据库集成测试

- 条件更新只有一个事务成功（并发启动）
- 项目启动事务：运行记录、5 个阶段、首个任务、Outbox 同时存在或同时回滚
- `project_runtimes.project_id` 唯一约束阻止重复启动
- 并发上限计数在项目锁内准确
