## 2. 产品概述

### 2.1 背景

源码安全评估通常涉及环境准备、代码检索、漏洞分析、漏洞验证、攻击路径梳理和报告编制。各环节依赖多类工具与人工协作，存在执行过程不透明、结果难追溯、交付标准不统一等问题。

本系统面向源码项目提供统一的自动化安全评估工作台，在独立隔离环境中完成任务调度与分析，持续记录阶段状态、执行日志、资源消耗和评估结果，最终输出可追溯的漏洞、攻击路径及安全评估报告。

### 2.2 产品目标

1. 支持源码目录或代码仓库快速接入并创建评估项目。
2. 在项目级独立隔离环境中自动完成安全评估流程。
3. 实时展示执行阶段、角色状态、交互消息、日志和资源消耗。
4. 形成结构化漏洞记录、攻击路径和标准化评估报告。
5. 保证任务过程、分析证据和执行结果可查询、可追溯。

### 2.3 成功指标

示例项目须完整完成“接入—分析—验证—报告”流程；阶段和角色状态可查询；评估结果包含报告及漏洞证据；状态、日志和资源变化实时推送；所有结果可追溯至项目及执行阶段。

### 2.4 产品范围

#### 2.4.1 本期范围

- 系统初始化、用户登录和登录态识别。
- 项目创建、查询、启动、停止和删除。
- 隔离环境创建、启动、停止和销毁。
- 源码读取、目录遍历、关键字搜索和受控命令执行。
- 多角色任务分发、阶段推进、状态汇总和失败记录。
- 漏洞发现、验证、证据保存和结果查询。
- 攻击路径整理、漏洞关联和影响说明。
- 报告生成、在线预览和文件下载。
- 实时状态、消息、日志和资源消耗监控。
- 系统运行参数和隔离环境配置管理。

#### 2.4.2 非本期范围

本期不包含多租户、统一身份认证、漏洞工单与复测闭环、第三方平台深度集成、多项目风险分析及移动端。

## 4. 核心业务流程

### 4.1 首次初始化与登录

1. 管理员访问系统初始化入口。
2. 系统确认尚未完成初始化。
3. 管理员设置初始账户。
4. 系统保存密码哈希并完成初始化。
5. 用户通过用户名和密码登录，成功后进入项目列表。

### 4.2 项目评估主流程

1. 用户填写项目名称、源码来源、任务说明和隔离环境类型。
2. 系统校验输入并创建项目，项目状态为 `created`。
3. 用户启动任务，系统创建并准备项目专属隔离环境。
4. 环境准备成功后，项目状态变为 `running`。
5. 调度模块依次推进环境扫描、代码分析、漏洞验证和报告生成。
6. 各阶段按需向执行角色分发任务，并持续保存状态、日志、消息和资源数据。
7. 分析结果保存为漏洞记录；多个漏洞可按利用顺序组成攻击路径。
8. 系统汇总执行过程与评估结果，生成最终报告。
9. 所有阶段成功后，项目状态变为 `completed`；用户可查看或下载报告。

### 4.3 停止流程

1. 用户对 `running` 项目发起停止操作。
2. 系统停止继续分发新任务，并向当前执行任务发出终止信号。
3. 当前阶段不再继续推进，项目状态变为 `stopped`。
4. 停止前已保存的阶段、漏洞、攻击路径、消息、日志、资源和报告数据继续保留。
5. 隔离环境按系统配置停止或销毁。

### 4.4 删除流程

1. 用户对非 `running` 项目发起删除操作。
2. 系统展示不可恢复提示并要求二次确认。
3. 确认后，系统删除项目及关联的阶段、角色任务、漏洞、攻击路径、消息、日志、资源和报告记录。
4. 系统同步清理该项目的日志、报告和临时工作目录，并销毁隔离环境。
5. 删除失败时返回失败项，不得将项目误标记为删除成功。

## 5. 状态模型

### 5.1 项目状态

| 状态 | 说明 | 可执行操作 |
| --- | --- | --- |
| `created` | 项目已创建，尚未运行 | 查看、启动、删除 |
| `running` | 评估任务执行中 | 查看、停止 |
| `completed` | 评估任务成功完成 | 查看结果、下载报告、删除 |
| `failed` | 环境或执行阶段发生不可恢复错误 | 查看错误、删除 |
| `stopped` | 用户主动停止任务 | 查看已保存结果、删除 |

状态流转规则：

- `created → running → completed`
- `created → running → failed`
- `created → running → stopped`
- 项目启动必须以隔离环境准备成功为前提。
- MVP 不支持对 `completed`、`failed` 或 `stopped` 项目直接重新执行；重新评估需创建新项目。
- 同一项目同一时刻仅允许存在一个运行任务。

### 5.2 执行阶段

| 顺序 | 阶段 | 说明 |
| --- | --- | --- |
| 1 | `environment_scan` | 检查源码、依赖、技术栈和运行环境 |
| 2 | `code_analysis` | 遍历源码并识别潜在漏洞 |
| 3 | `vulnerability_verify` | 验证漏洞可达性、触发条件和影响 |
| 4 | `report_generate` | 汇总漏洞、攻击路径和修复建议 |
| 5 | `done` | 全部流程结束 |

阶段状态统一为 `idle`、`running`、`success`、`failed`。前置阶段成功后方可进入下一阶段；任一关键阶段失败时，后续阶段不再启动，项目进入 `failed`。

### 5.3 执行角色

系统至少提供以下六类角色：

| 执行角色 | 主要职责 |
| --- | --- |
| 通用处理角色 | 解析任务、汇总上下文、协调通用操作 |
| 环境检查角色 | 识别项目结构、技术栈、依赖和运行条件 |
| 代码分析角色 | 检索源码并发现潜在安全问题 |
| 漏洞验证角色 | 验证触发条件、证据、复现步骤和影响 |
| 报告整理角色 | 汇总评估结果并生成标准报告 |
| 运维辅助角色 | 管理隔离环境、执行受控命令并采集资源数据 |

每次角色执行必须形成独立任务记录，包含任务内容、所属项目、所属阶段、开始时间、结束时间、执行状态、结果摘要和错误信息。角色任务状态为 `idle`、`running`、`success`、`failed`。

## 6. 功能需求

需求优先级采用 P0、P1、P2：P0 为上线必需，P1 为重要能力，P2 为体验增强。

### 6.1 认证与初始化

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | :---: | --- |
| FR-AUTH-001 | 系统首次使用时支持初始化管理员账户 | P0 | 未初始化时可创建管理员；初始化完成后不得重复执行 |
| FR-AUTH-002 | 用户可使用用户名和密码登录 | P0 | 凭证正确进入项目列表；错误时返回明确提示 |
| FR-AUTH-003 | 系统识别并校验用户登录态及角色 | P0 | 未登录请求被拒绝；越权访问系统配置被拒绝 |
| FR-AUTH-004 | 密码仅以安全哈希形式保存 | P0 | 数据库及日志中不得出现明文密码 |

### 6.2 项目管理

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | :---: | --- |
| FR-PROJ-001 | 用户可创建评估项目 | P0 | 必填项校验通过后生成唯一项目 ID，初始状态为 `created` |
| FR-PROJ-002 | 支持本地源码路径和代码仓库地址两类来源 | P0 | 来源类型与地址格式匹配；不可访问时给出原因 |

| FR-PROJ-004 | 项目详情展示基本信息、阶段状态、漏洞数、攻击路径数和报告状态 | P0 | 统计值与关联记录一致 |
| FR-PROJ-005 | 用户可启动 `created` 状态项目 | P0 | 重复启动被拒绝；环境准备成功后进入执行阶段 |
| FR-PROJ-006 | 用户可停止 `running` 状态项目 | P0 | 停止后不再推进阶段，已保存数据保留 |

项目名称、源码类型、源码地址、任务说明和隔离环境类型均为必填项。源码类型限 `local` 或 `repository`，地址必须与类型匹配且可访问；隔离环境类型从管理员启用项中选择。

### 6.5 实时监控

| 编号 | 需求 | 优先级 | 验收要点 |

| FR-MON-002 | 展示各角色任务及状态 | P0 | 可识别运行、成功和失败角色 |
| FR-MON-003 | 展示角色交互消息 | P1 | 消息包含角色、类型、内容和时间 |
| FR-MON-004 | 展示滚动运行日志，并区分日志级别 | P0 | 新日志实时追加，可回看历史日志 |

### 6.6 漏洞管理

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | :---: | --- |
| FR-VULN-001 | 保存分析发现的漏洞 | P0 | 自动生成项目内唯一漏洞编号 |
| FR-VULN-002 | 漏洞列表展示标题、风险等级、验证状态和文件位置 | P0 | 支持按风险等级和验证状态筛选 |
| FR-VULN-003 | 漏洞详情展示影响、触发条件、证据、复现步骤和验证代码 | P0 | 内容可追溯至源码位置及所属项目 |
| FR-VULN-004 | 记录漏洞验证状态 | P0 | 至少区分待验证、验证通过、验证失败 |
| FR-VULN-005 | 新漏洞产生时推送实时消息 | P1 | 监控页可及时展示漏洞摘要 |

风险等级统一为 `critical`、`high`、`medium`、`low`、`info`；验证状态统一为 `pending`、`verified`、`rejected`。

### 6.8 报告

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | :---: | --- |
| FR-REP-001 | 评估完成后自动生成报告 | P0 | 报告状态可查询，生成成功后推送 `report_ready` |
| FR-REP-002 | 支持在线预览完整报告 | P0 | 页面内容与保存的报告版本一致 |
| FR-REP-003 | 支持下载报告文件 | P0 | 文件可正常打开，下载失败时给出明确提示 |

## 7. 页面需求

### 7.1 页面清单

| 页面 | 核心内容 | 核心操作 |

### 7.2 通用交互要求

- 列表页提供加载中、无数据和失败状态，写操作防止重复提交。
- 停止和删除必须二次确认；各类状态使用统一文案及视觉标识。
- 错误提示不得暴露堆栈或敏感信息；报告未就绪时禁用下载。

| --- | --- |
| 初始化与认证 | `POST /api/system/init`、`POST /api/system/login` |
| 项目管理 | `POST /api/projects`、`GET /api/projects`、`GET /api/projects/{project_id}`、`DELETE /api/projects/{project_id}` |
| 任务控制 | `POST /api/projects/{project_id}/start`、`POST /api/projects/{project_id}/stop` |
| 过程查询 | `GET /api/projects/{project_id}/stages`、`GET /api/projects/{project_id}/workers`、`GET /api/projects/{project_id}/logs`、`GET /api/projects/{project_id}/resources` |
| 结果查询 | `GET /api/projects/{project_id}/vulnerabilities`、`GET /api/projects/{project_id}/attack-paths`、`GET /api/projects/{project_id}/report` |
| 实时订阅 | `WS /api/projects/{project_id}/stream` |

接口通用要求：

- 接口统一返回业务状态、提示信息和数据主体，列表接口支持分页。
- 所有项目接口校验登录态、项目权限和当前状态，重复请求不得产生重复任务。
- WebSocket 建连时校验权限；接口文档需说明请求、响应、错误码和示例。

## 9. 数据需求

### 9.1 核心数据实体

| 数据表 | 用途 |
| --- | --- |
| `users` | 保存用户、密码哈希、角色和状态 |
| `projects` | 保存源码信息、任务说明、项目状态和创建者 |
| `runtime_stages` | 保存项目阶段状态、起止时间和错误 |
| `worker_tasks` | 保存角色任务、执行状态和结果摘要 |
| `vulnerabilities` | 保存漏洞风险、位置、证据和验证结果 |
| `attack_paths` | 保存攻击路径摘要和最终影响 |
| `attack_path_items` | 保存路径步骤、顺序及漏洞关联 |
| `chat_messages` | 保存角色交互消息 |
| `runtime_logs` | 保存阶段及角色任务日志 |
| `resource_usages` | 保存 CPU、内存和 token 采样数据 |
| `reports` | 保存 Markdown、HTML 和报告文件路径 |

所有业务表使用唯一主键；项目关联数据包含 `project_id`，阶段、角色任务、漏洞、路径步骤按业务关系设置外键。具体字段以原始需求和数据库设计为准。

### 9.2 数据一致性

- 删除项目时级联清理关联记录和文件。
- 路径关联漏洞必须属于同一项目；阶段、任务、日志和资源记录必须关联有效项目。
- 阶段或任务结束时记录结束时间，失败时记录错误；统计数据以持久化结果为准。
- 时间由服务端生成，统一采用 UTC 或约定时区存储。

### 9.3 文件存储

| 文件类型 | 存储路径 |
| --- | --- |
| 运行日志 | `runtime_logs/{project_id}/` |
| 报告文件 | `reports/{project_id}/` |
| 临时执行文件 | `workspace/{project_id}/` |

目录只能由系统按项目 ID 创建和访问，禁止通过用户输入直接拼接未校验路径。

## 10. 非功能需求

### 10.1 安全性

- 密码使用安全哈希算法存储，认证信息不得写入日志。
- 所有非公开接口均进行身份认证和权限校验。
- 源码仅以只读方式挂载，执行产生的文件写入项目临时目录。
- 隔离环境限制文件访问、命令权限、运行时间和资源配额。
- 源码路径、仓库地址、文件路径和命令参数必须进行合法性校验，防止路径穿越和命令注入。
- 报告下载需校验项目访问权限，不允许通过文件路径直接访问。
- 前端展示日志、证据和报告内容时需防止脚本注入。
- 敏感配置在页面及日志中脱敏展示。

### 10.2 性能与容量

- 普通查询接口在正常负载下的服务端 P95 响应时间不超过 2 秒，不含源码分析和报告生成等异步任务。
- 创建、启动、停止等操作应在 3 秒内返回已受理或明确失败结果。
- 日志和资源查询采用分页或时间窗口加载，禁止一次返回全量大数据。
- 并发任务数由管理员配置；系统达到上限时应拒绝或排队处理，并向用户明确展示状态。

### 10.3 可靠性

- 项目、阶段和角色任务状态写入持久化存储，服务重启后可查询。
- WebSocket 中断不影响后台任务执行。
- 单个角色任务失败不得导致已保存结果丢失。
- 报告生成失败时保留漏洞和攻击路径结果，并记录失败原因。
- 项目删除须具备幂等性，部分清理失败时可识别未完成项。

### 10.4 可观测性

- 关键操作至少记录项目 ID、操作者、操作类型、时间和结果。
- 环境创建、任务调度、角色执行、报告生成和清理失败均记录错误日志。
- 资源采样至少包含 CPU、内存和 token 使用量。
- 日志级别统一为 `debug`、`info`、`warning`、`error`。

### 10.5 兼容性与可用性

- Web 端适配主流桌面浏览器最新两个稳定版本。
- 页面在 1440×900 及以上常见桌面分辨率下可正常使用。
- 核心操作提供明确的成功、失败和处理中反馈。
- 长耗时任务采用异步执行，页面刷新或离开不应终止任务。

## 11. 异常处理

| 场景 | 处理规则 |
| --- | --- |
| 源码路径不存在或无权限 | 阻止创建或启动，并说明不可访问原因 |
| 仓库地址无效或拉取失败 | 项目不进入分析阶段，记录错误并置为 `failed` |
| 隔离环境创建失败 | 项目置为 `failed`，不得启动后续阶段 |
| 阶段执行超时 | 终止阶段任务，记录超时原因，项目置为 `failed` |
| 用户重复启动项目 | 返回状态冲突，不创建重复任务 |
| 用户停止非运行项目 | 返回状态冲突，不改变现有状态 |
| 用户删除运行中项目 | 拒绝删除，提示先停止任务 |
| WebSocket 中断 | 前端自动重连，并通过查询接口补齐断线期间数据 |
| 报告生成失败 | 保留已有评估结果，报告标记失败并允许查看错误 |
| 文件清理部分失败 | 记录失败路径并返回清理未完成，不伪造成功结果 |

## 12. 验收标准

### 12.1 核心验收用例

| 编号 | 前置条件 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| AC-001 | 系统未初始化 | 提交管理员初始化信息 | 成功创建管理员；再次初始化被拒绝 |
| AC-002 | 存在有效用户 | 使用正确及错误凭证登录 | 正确凭证进入项目列表；错误凭证无法登录 |
| AC-003 | 用户已登录 | 分别使用本地路径和仓库地址创建项目 | 创建成功，项目状态为 `created`，来源信息正确 |
| AC-004 | 存在 `created` 项目 | 启动评估任务 | 独立隔离环境准备完成，项目变为 `running` |
| AC-005 | 项目运行中 | 持续查看实时监控页 | 可看到阶段、角色、消息、日志和资源变化 |
| AC-006 | 项目运行中 | 等待代码分析和漏洞验证 | 可查询漏洞列表与详情，包含证据和验证状态 |
| AC-007 | 已形成可组合漏洞 | 查看攻击路径 | 可看到关联漏洞、利用顺序和最终影响 |
| AC-008 | 所有必要阶段成功 | 查看并下载报告 | 项目变为 `completed`；报告章节完整且文件可打开 |
| AC-009 | 项目运行中 | 停止任务 | 项目变为 `stopped`；阶段不再推进；已有结果保留 |
| AC-010 | 项目非运行状态 | 确认删除项目 | 关联记录、隔离环境和项目目录均被清理 |
| AC-011 | 普通使用者已登录 | 访问系统配置接口和页面 | 访问被拒绝 |
| AC-012 | 示例项目可访问 | 完整执行一次评估 | 完成接入、分析、验证、攻击路径整理和报告输出演示 |
