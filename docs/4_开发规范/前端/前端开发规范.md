# 自动化安全评估系统前端开发规范

## 1. 文档说明

### 1.1 目的

本文档定义自动化安全评估系统（ASA System）MVP 前端工程的技术选型、目录结构、编码规则、组件边界、数据通信、页面交互、安全、可访问性、性能、测试和交付门禁。前端开发、代码评审和测试验收必须以本文档为统一基线。

### 1.2 设计依据

- `docs/1_PRD/自动化安全评估系统-PRD.md`
- `docs/3_概要设计/自动化安全评估系统-概要设计总纲.md`
- `docs/4_开发规范/API接口文档.md`

发生冲突时，业务范围与验收标准以 PRD 为准，技术路线与工程边界以概要设计总纲为准，请求、响应、错误码和实时事件以 API 接口文档为准。不得在前端自行扩展后端状态值、业务字段或权限规则。

### 1.3 适用范围

本规范适用于 `packages/asa-ui/` 下的 Vue 单页应用、`packages/contracts/` 中供前端使用的接口契约，以及 `tests/e2e/` 下的前端端到端测试。

MVP 前端范围包括：

- 系统初始化、登录、登录态恢复和退出。
- 项目创建、列表、详情、启动、停止和删除。
- 阶段、角色任务、消息、日志和资源消耗的实时监控。
- 漏洞列表、筛选、详情、证据和源码位置展示。
- 攻击路径列表、步骤、关联漏洞和最终影响展示。
- 报告状态、在线预览和 Markdown、HTML 文件下载。
- 管理员系统配置查看与更新。

多租户、统一身份认证、项目共享授权、复测工单、多项目分析和移动端专项适配不在 MVP 范围内。

### 1.4 规范级别

- “必须”表示合并前不可违反的要求。
- “禁止”表示不得采用的实现。
- “应”表示默认执行，偏离时必须在评审中说明理由和风险。
- “可”表示按实际场景选择。

## 2. 基本原则

### 2.1 业务状态以服务端为准

PostgreSQL 持久化数据是项目、阶段、角色任务、漏洞、攻击路径和报告状态的权威来源。Pinia、组件状态和 WebSocket 事件只用于页面展示，不得作为业务成功的最终依据。

页面刷新、重新进入项目或 WebSocket 断线后，必须通过 REST API 恢复权威快照，再接收增量事件。不得根据前端定时器推断异步任务已完成。

### 2.2 单一职责

- 页面组件负责路由参数、页面级数据编排和区域布局。
- 业务组件负责一个明确业务区域及其交互。
- 展示组件只通过 `props` 接收数据并通过 `emits` 上报事件。
- Composable 负责可复用的有状态逻辑和生命周期管理。
- Store 负责跨页面或跨区域共享状态，不代替所有组件本地状态。
- Service 负责 HTTP、WebSocket、下载等外部通信，不包含页面展示逻辑。

组件同时承担请求、状态转换、大段模板渲染和弹窗流程时必须拆分。只使用一次且逻辑简单的片段不得为追求目录完整而过度封装。

### 2.3 类型优先

- 所有业务代码使用 TypeScript，开启严格类型检查。
- 禁止使用隐式 `any` 和无理由的显式 `any`。
- API、WebSocket、路由参数和浏览器存储均视为不可信边界，使用明确类型和校验函数收窄。
- 状态、风险等级、角色和事件类型必须复用 `packages/contracts/` 的闭集类型。
- 类型断言不得用于掩盖接口不一致；契约不一致时应修正生成类型或边界转换。

### 2.4 安全默认

日志、角色消息、漏洞证据、验证代码、报告 Markdown 和外部 URL 均按不可信内容处理。默认以纯文本展示，只有后端已清理的 `report_html` 可以进入受控 HTML 预览容器。

### 2.5 简单优先

- 同类逻辑出现三次或形成稳定业务概念后再抽取公共能力。
- 不为单个页面建立通用渲染引擎、动态表单引擎或全局事件总线。
- 不引入与既定技术栈重复的状态、请求、UI 或图表框架。
- 优先使用清晰的组合函数和数据转换函数，不使用深层继承。

## 3. 技术栈与工程约束

### 3.1 必选技术

| 分类 | 技术 | 使用约束 |
| --- | --- | --- |
| 核心框架 | Vue 3、TypeScript | 使用 Composition API 和 `<script setup lang="ts">` |
| 构建工具 | Vite | 负责开发服务、生产构建和环境变量注入 |
| UI 组件 | Element Plus | 用于表单、表格、分页、对话框、反馈和基础布局 |
| 路由 | Vue Router | 使用路由元信息实现登录和角色守卫 |
| 状态管理 | Pinia | 只保存跨组件或跨页面共享状态 |
| HTTP | Axios | 统一实例、Cookie、CSRF、超时和错误转换 |
| 实时通信 | 原生 WebSocket 封装 | 实现心跳、重连、去重和断线补偿 |
| 图表 | Apache ECharts | 展示 CPU、内存和 token 趋势 |
| 单元测试 | Vitest、Vue Test Utils | 测试组件、Store、Composable 和数据转换 |
| 端到端测试 | Playwright | 覆盖关键用户流程和浏览器交互 |
| 代码质量 | ESLint、Prettier、`vue-tsc` | 分别负责静态规则、格式和类型检查 |

未经技术评审不得引入 React、Tailwind CSS、其他 UI 组件库、其他状态管理库、其他 HTTP 客户端或封装 WebSocket 的第三方框架。

### 3.2 依赖管理

- 仓库只使用根目录锁文件对应的包管理器，禁止混用 `npm`、`pnpm` 和 `yarn` 生成多个锁文件。
- 根 `package.json` 必须通过 `packageManager` 固定包管理器及版本。
- Node.js 版本必须通过仓库级版本文件固定，开发、CI 和生产构建保持一致。
- 运行依赖放入 `dependencies`，构建、类型、Lint 和测试依赖放入 `devDependencies`。
- 禁止直接依赖未锁定的 Git 分支、临时压缩包和个人本地路径。
- 新增依赖前必须确认许可证、维护状态、包体积、浏览器兼容性和是否与现有能力重复。
- 依赖升级应单独说明破坏性变化、构建产物变化和回归范围。

### 3.3 环境变量

浏览器可访问的环境变量统一使用 `VITE_` 前缀，并在 `src/env.d.ts` 中声明类型。前端环境变量只能保存公开的构建配置，不得包含密码、Cookie、Token、私有仓库凭证、证书或服务端密钥。

API 和 WebSocket 默认通过 Nginx 同源访问，代码中使用相对路径 `/api/v1`，不得写死域名、端口或生产地址。确需配置外部地址时必须通过环境变量注入并校验协议。

### 3.4 TypeScript 配置

- 必须启用 `strict`、`noImplicitAny`、`noUncheckedIndexedAccess` 和 `useDefineForClassFields`。
- 应启用未使用变量、未使用参数和不完整返回路径检查。
- 生产代码不得通过关闭类型检查或增加全局忽略规则解决错误。
- `@ts-ignore` 禁止使用；确需绕过第三方类型问题时使用带原因的 `@ts-expect-error`，并关联清理任务。
- 路径别名只保留少量稳定入口，例如 `@/` 指向 `src/`，不得为每个目录建立别名。

## 5. 命名与代码风格

### 5.1 文件命名

| 类型 | 命名规则 | 示例 |
| --- | --- | --- |
| Vue 组件 | PascalCase | `ProjectStatusTag.vue` |
| 页面组件 | PascalCase，以 `Page` 结尾 | `ProjectListPage.vue` |
| 布局组件 | PascalCase，以 `Layout` 结尾 | `AppLayout.vue` |
| Composable | camelCase，以 `use` 开头 | `useProjectStream.ts` |
| Pinia Store | kebab-case，以 `.store.ts` 结尾 | `auth.store.ts` |
| API 模块 | kebab-case，以 `.api.ts` 结尾 | `project.api.ts` |
| 类型文件 | kebab-case，以 `.types.ts` 结尾 | `monitoring.types.ts` |
| 常量文件 | kebab-case，以 `.constants.ts` 结尾 | `status.constants.ts` |
| 工具文件 | kebab-case | `format-bytes.ts` |
| 单元测试 | 与被测文件同名，以 `.spec.ts` 结尾 | `useProjectStream.spec.ts` |

目录使用 kebab-case。组件名至少包含两个单词，避免与原生 HTML 元素冲突。

### 5.2 标识符命名

- 变量和函数使用 camelCase。
- 类型、接口和组件使用 PascalCase。
- 常量对象使用 camelCase；真正的跨模块固定常量可使用 UPPER_SNAKE_CASE。
- 布尔值使用 `is`、`has`、`can` 或 `should` 前缀。
- 事件处理函数使用 `handle` 前缀，例如 `handleProjectStart`。
- 传给组件的回调属性不使用 `on` 前缀模拟 React；Vue 组件通过 `emits` 上报事件。
- ID 名称必须体现实体，例如 `projectId`、`stageId`，禁止使用含义不明的 `id` 跨越多个作用域。
- 时间字段保留接口命名语义；视图模型中可转为 `startedAt`，但转换必须集中且可测试。

### 5.3 Vue 文件结构

单文件组件按以下顺序组织：

1. `<script setup lang="ts">`
2. `<template>`
3. `<style scoped>` 或无样式块

组件的导入、类型、`props`、`emits`、依赖、状态、计算属性、方法和生命周期按逻辑分组。避免使用分隔注释制造过长文件；文件过长通常表示职责需要拆分。

示例：

```vue
<script setup lang="ts">
import { computed } from 'vue'

import type { ProjectStatus } from '@asa/contracts'

import { PROJECT_STATUS_TEXT } from '../constants/status.constants'

interface Props {
  status: ProjectStatus
}

const props = defineProps<Props>()

const statusText = computed(() => PROJECT_STATUS_TEXT[props.status])
</script>

<template>
  <span class="project-status" :data-status="status">
    {{ statusText }}
  </span>
</template>
```

示例中的状态映射应从模块常量导入，此处仅展示组件结构。

### 5.4 格式与静态规则

- 统一由 Prettier 格式化，不以个人编辑器格式覆盖仓库配置。
- ESLint 必须覆盖 Vue、TypeScript、Promise 和无障碍相关规则。
- 导入按第三方、仓库内部、相对路径和类型导入分组，组间保留空行。
- 类型导入使用 `import type`。
- 禁止提交 `console.log`、`debugger`、未处理 Promise 和空的异常捕获。
- 不使用嵌套三元表达式表达业务状态。
- 单个函数应保持一个清晰目的；条件复杂时提取有业务名称的判断函数。
- 注释解释约束、原因和风险，不重复描述代码表面行为。

## 6. HTML 与组件规范

### 6.1 语义化 HTML

- 页面主体使用 `main`，全局导航使用 `nav`，独立内容区使用 `section`，辅助信息使用 `aside`。
- 标题按页面结构使用 `h1` 至 `h6`，不得为视觉大小跳级。
- 可点击操作使用 `button` 或链接，不得使用带点击事件的 `div`、`span` 模拟控件。
- 页面跳转使用链接语义，执行启动、停止、删除和提交使用按钮语义。
- 表单控件必须关联可见 `label`；仅图标按钮必须提供可访问名称。
- 表格数据使用原生表格语义或具备等价语义的 Element Plus 组件。
- 时间使用可读文本，并在可行时提供标准 ISO 8601 值。

### 6.2 组件边界

- 页面组件只组织页面，不堆叠可复用业务细节。
- 组件 `props` 必须只读并明确类型，不得在子组件内修改对象属性。
- `emits` 必须声明事件名称和参数类型。
- 双向绑定只用于真正的受控输入，业务对象更新优先使用明确事件。
- 插槽用于内容组合，不用于绕过清晰的 `props` 接口。
- 不向通用组件传入完整 Store 或 Axios 响应对象。
- 组件不得依赖父组件 DOM 结构或通过全局选择器修改其他组件。
- 同一模块中出现三个结构和行为稳定一致的实现后再抽取公共组件。

### 6.3 Element Plus 使用

- 统一通过主题变量定义颜色、圆角、间距和控件尺寸，不分散覆盖内部类名。
- 二次确认使用 `ElDialog`，不得使用浏览器原生 `alert`、`confirm`。
- 表单使用 `ElForm` 的规则和错误定位，但服务端字段错误仍需映射到对应控件。
- `ElMessage` 用于短暂操作反馈，关键错误同时保留在页面错误区，避免信息消失后无法追溯。
- 表格必须提供稳定 `row-key`，分页切换时保持筛选和排序条件。
- 不直接依赖 Element Plus 未公开的 DOM 结构和内部类名。

### 6.4 状态组件

项目、阶段、角色、风险、验证、日志和报告状态必须使用统一映射。状态映射至少包含：

- 接口值。
- 中文文案。
- 颜色或视觉等级。
- 图标。
- 可访问文本。
- 可执行操作。

颜色不得作为唯一识别方式。未知状态不得静默映射为成功，应展示“未知状态”，记录可诊断信息，并保持页面可继续使用。

## 7. 路由与权限

### 7.1 路由清单

| 路由 | 页面 | 访问条件 |
| --- | --- | --- |
| `/system/init` | 系统初始化页 | 系统未初始化 |
| `/login` | 登录页 | 未登录 |
| `/projects` | 项目列表页 | 已登录 |
| `/projects/new` | 项目创建页 | 已登录 |
| `/projects/:projectId` | 项目详情页 | 已登录且有项目权限 |
| `/projects/:projectId/monitor` | 实时监控页 | 已登录且有项目权限 |
| `/projects/:projectId/vulnerabilities` | 漏洞列表页 | 已登录且有项目权限 |
| `/projects/:projectId/vulnerabilities/:vulnerabilityId` | 漏洞详情页 | 已登录且有项目权限 |
| `/projects/:projectId/attack-paths` | 攻击路径列表页 | 已登录且有项目权限 |
| `/projects/:projectId/attack-paths/:attackPathId` | 攻击路径详情页 | 已登录且有项目权限 |
| `/projects/:projectId/report` | 报告页 | 已登录且有项目权限 |
| `/knowledge` | 知识库管理页 | 管理员 |
| `/system/config` | 系统配置页 | 管理员 |
| `/:pathMatch(.*)*` | 404 页面 | 所有人 |

### 7.2 路由规则

- 页面组件必须懒加载，初始化和登录页可放入独立公共分包。
- 路由名称使用稳定 PascalCase 标识，不以中文文案作为名称。
- `projectId` 等路由参数必须校验为 UUID，格式错误直接进入 404 或参数错误页，不发无效请求。
- 列表筛选、分页、排序和活动页签应同步到 URL 查询参数，刷新和分享地址后可恢复。
- 页面标题根据当前页面和项目名称更新。
- 路由离开前只在存在未提交表单变更时拦截，不阻止后台任务继续执行。
- 权限守卫用于改善导航体验，后端权限校验仍是最终边界。

### 7.3 初始化和登录守卫

应用启动时先调用 `GET /api/v1/system/status`：

1. `initialized=false` 时只允许进入初始化页。
2. `initialized=true` 且未登录时进入登录页。
3. 已登录用户访问初始化页或登录页时进入项目列表。
4. 普通用户访问系统配置页时进入 403 页面。
5. 收到 `401 AUTH_REQUIRED` 或 `SESSION_EXPIRED` 时清理内存中的用户状态，保留安全的原始目标路由并进入登录页。

不得依赖读取 `HttpOnly` Cookie 判断登录状态。登录态必须通过服务端接口确认。

## 8. 状态管理

### 8.1 状态分类

| 状态类型 | 存放位置 | 示例 |
| --- | --- | --- |
| 组件临时状态 | 组件内 | 弹窗开关、输入焦点、折叠状态 |
| 页面查询状态 | URL 或页面 Composable | 页码、筛选、排序、时间窗口 |
| 跨页面会话状态 | Pinia | 当前用户、角色、初始化状态 |
| 项目共享展示状态 | 模块 Store | 当前项目概览、实时连接状态 |
| 权威业务状态 | 服务端 | 项目、阶段、漏洞、报告状态 |
| 无敏感偏好 | `localStorage` | 主题、表格密度 |
| 当前标签页恢复信息 | `sessionStorage` | 按项目记录的最后事件序号 |

认证 Cookie、密码、CSRF Token、仓库凭证、报告正文、漏洞证据和运行日志不得写入 `localStorage`。

### 8.2 Pinia 规则

- Store 使用 setup 风格，按业务模块拆分。
- State 保存原始共享数据，派生值使用 getter，不重复保存。
- 异步 Action 必须明确加载、成功和错误路径。
- Store 不直接控制弹窗、消息提示和 DOM。
- 组件卸载后不再需要的数据应及时释放，尤其是日志、资源曲线和事件去重缓存。
- Store 测试必须覆盖状态转换、并发请求和异常恢复。

### 8.3 请求竞态

- 搜索和筛选请求使用取消机制或请求序号，旧响应不得覆盖新条件的结果。
- 切换 `projectId` 时必须取消旧项目请求、关闭旧 WebSocket 并清理项目级状态。
- 写操作进行中禁用对应按钮，避免重复提交。
- 查询请求可并发时使用独立加载状态，不以一个全局 `isLoading` 阻塞整个页面。

## 9. REST API 规范

### 9.1 Axios 实例

应用只创建一个基础 Axios 实例，并按模块封装 API 函数：

- `baseURL` 为 `/api/v1`。
- `withCredentials` 为 `true`。
- 设置合理请求超时；长耗时任务仍由异步接口受理，不通过无限延长 HTTP 超时解决。
- 请求拦截器只处理公共请求头、CSRF 和 `X-Request-ID`。
- 响应拦截器只解包统一响应、转换已知错误和处理全局认证失效。
- 业务错误文案、页面跳转和重试决策由调用模块处理。

### 9.2 响应与错误

除文件下载和 WebSocket 外，统一响应为：

```ts
interface ApiResponse<T> {
  code: string
  message: string
  data: T
  request_id: string
}
```

错误对象至少保留：

- HTTP 状态。
- 业务 `code`。
- 用户可读 `message`。
- `request_id`。
- 字段校验错误。
- `Retry-After` 或 `retry_after_seconds`。

页面展示错误时应附带可复制的 `request_id`，不得显示堆栈、SQL、宿主机路径或原始响应对象。

### 9.3 认证、Cookie 与 CSRF

- `asa_session` 为 `HttpOnly` Cookie，前端不得读取或复制。
- 已认证的 `POST`、`PUT`、`PATCH`、`DELETE` 请求必须携带 `X-CSRF-Token`。
- CSRF 值只按接口契约从可读 Cookie 或指定端点获取，不得写入持久化存储和日志。
- 退出成功后清理 Pinia、项目缓存、事件序号和 WebSocket。
- `401` 只触发一次统一登录跳转，避免多个并发失败重复弹窗。
- `403` 区分角色权限、项目权限和 CSRF 失败，不将所有情况误判为登录过期。

### 9.4 幂等写操作

启动、停止和删除必须携带 `Idempotency-Key`：

- 用户首次确认操作时生成一个 UUID。
- 请求超时或网络失败重试时复用原 Key。
- 操作得到明确终态或用户发起新的独立操作后才生成新 Key。
- Key 只保存在当前操作上下文，不作为业务数据长期持久化。
- 收到 `409 IDEMPOTENCY_KEY_REUSED` 时停止自动重试并提示用户刷新状态。

项目创建和配置更新不得因双击产生并发请求。按钮禁用只是体验保护，后端幂等和版本冲突仍必须正确处理。

### 9.5 分页与大数据

- 普通列表使用 `page`、`page_size`，默认每页 20 条，最大值遵循接口契约。
- 日志、消息和资源使用 `cursor`、`limit`，不得用数组长度模拟游标。
- 日志和资源必须按时间窗口增量加载，禁止一次请求全部历史。
- 筛选条件变化时清空旧游标并回到第一页。
- API 原始模型转换为视图模型的函数必须为纯函数并有单元测试。

### 9.6 文件下载

- 报告下载通过受权接口发起，不拼接内部文件路径。
- 下载前检查 `report_status=ready` 和 `download_available=true`。
- 使用响应头中的安全文件名；缺失时使用项目 ID 和格式生成受控文件名。
- 对二进制响应中的 JSON 错误进行识别，不能把错误正文保存成报告文件。
- 下载失败必须保留当前报告预览并提供可重试反馈。

## 10. WebSocket 实时通信

### 10.1 客户端职责

`services/realtime/` 只维护一个项目连接实例，负责：

- 使用 Cookie 完成握手并请求 `asa.v1` 子协议。
- 发送应用层 `ping` 并处理 `pong`。
- 解析和校验事件包。
- 使用 `event_id` 去重。
- 按 `sequence` 顺序处理事件。
- 记录最后处理成功的序号。
- 指数退避重连并加入随机抖动。
- 识别关闭码并决定重连、补偿或退出。
- 向模块暴露连接状态和类型化事件，不直接修改页面 DOM。

心跳周期、超时、事件保留窗口和发送缓冲不得在多个组件中写死，应集中为可配置常量，并以容量测试和接口约定为准。

### 10.2 事件类型

必须支持以下事件：

| 事件 | 前端处理 |
| --- | --- |
| `project_status` | 更新项目状态、停止意图和可执行操作 |
| `stage_status` | 更新对应阶段状态 |
| `worker_status` | 更新对应角色任务状态 |
| `chat_message` | 按消息 ID 追加角色消息 |
| `runtime_log` | 按日志 ID 追加日志 |
| `resource_usage` | 按采样 ID 追加资源点 |
| `vulnerability_found` | 更新漏洞摘要和计数，并提示新发现 |
| `report_ready` | 更新报告状态并启用预览、下载 |

未知事件类型不得导致连接中断。客户端应忽略未知载荷、记录脱敏诊断信息，并通过契约升级任务处理。

### 10.3 初始快照与增量

进入监控页时按以下顺序处理：

1. 清理其他项目的连接和未完成请求。
2. 读取当前项目在 `sessionStorage` 中的最后成功 `sequence`。
3. 建立带 `after_sequence` 的 WebSocket 并暂存到达事件。
4. 并发查询项目详情、阶段、任务、消息、日志、资源和已产生结果作为 REST 快照。
5. 应用快照后，按 `sequence` 升序处理暂存事件。
6. 成功处理事件后再更新最后序号。

若没有可用序号，从 `0` 开始连接并依赖 REST 快照校正。不得先把空页面当作真实的“无数据”状态。

### 10.4 去重与顺序

- 使用有上限的 `event_id` 集合去重，避免长期运行导致内存无限增长。
- `sequence` 小于或等于已处理序号的事件不重复应用。
- 发现序号跳跃时暂停直接更新，先触发对应 REST 补偿。
- 日志、消息和资源按服务端 ID 去重，不按文本和时间戳去重。
- 项目、阶段和角色状态使用服务端时间和序号决定新旧，不能依赖客户端到达顺序。

### 10.5 断线与关闭码

- 普通网络中断和 `1011` 使用指数退避重连，设置重试上限后的手动重试入口。
- `4001 SESSION_EXPIRED` 清理会话展示状态并进入登录页。
- `4003 PROJECT_ACCESS_DENIED` 停止重连并进入 403 页面。
- `4008 RATE_LIMITED` 遵循服务端等待信息，不立即循环重连。
- `4009 EVENT_GAP_TOO_LARGE` 调用项目详情、阶段、任务、消息、日志、资源和结果接口进行全量补偿，再使用最新可用序号重连。
- `4010 CLIENT_TOO_SLOW` 降低日志和资源渲染频率，完成 REST 补偿后再重连。

连接状态必须可见，至少区分“连接中”“实时”“重连中”“已断开”和“数据补偿中”。WebSocket 断开不得显示后台任务已停止。

### 10.6 高频数据

- 日志事件先进入内存队列，按帧或短时间批量更新视图。
- 可见日志行数设置上限，历史数据通过游标回看，不在 DOM 中无限追加。
- 资源采样按时间窗口保留并降采样，不把每次事件都触发完整 ECharts 重绘。
- 用户手动向上滚动后暂停自动跟随，提供“回到最新”按钮。
- 页面隐藏时降低图表刷新频率，但不得丢弃状态、漏洞和报告事件。

## 11. 页面与交互规范

### 11.1 通用页面状态

每个查询区域必须区分：

- 首次加载。
- 局部刷新。
- 有数据。
- 空数据。
- 可重试错误。
- 无权限。

骨架屏只用于结构稳定的首次加载。快速请求不应频繁闪烁全屏 Loading。局部请求失败不得清空仍然有效的旧数据。

### 11.2 项目操作矩阵

| 项目状态 | 允许操作 |
| --- | --- |
| `created` | 查看、启动、删除 |
| `running` | 查看、监控、停止 |
| `completed` | 查看结果、预览或下载报告、删除 |
| `failed` | 查看错误和已保存结果、删除 |
| `stopped` | 查看已保存结果、删除 |

不得为 `completed`、`failed` 或 `stopped` 项目提供原地重跑入口。操作按钮同时依据状态和权限控制；仅隐藏按钮不能代替服务端校验。

### 11.3 表单

- 标签、必填标记、帮助文本和错误文本必须与控件关联。
- 客户端校验用于快速反馈，服务端校验是最终规则。
- 项目创建必须校验项目名称、源码类型、源码地址、任务说明和隔离环境类型。
- `source_type=local` 与 `source_type=repository` 使用对应的地址提示，不展示或接收仓库明文凭证。
- 提交失败时保留用户输入；字段错误定位到控件，通用错误显示在表单顶部。
- 提交成功后才清理表单。
- 系统配置更新存在版本冲突时不得覆盖服务端新值，应提示刷新和对比。

### 11.4 停止和删除

- 停止与删除必须二次确认。
- 删除确认必须明确说明不可恢复，并要求用户确认项目名称。
- 运行中项目不显示可用删除操作；接口仍返回冲突时展示“请先停止项目”。
- 停止返回 `202` 后显示“停止请求已受理”，项目仍可能短暂保持 `running`，可结合 `stop_requested_at` 展示“停止中”视图状态，但不得新增后端项目状态值。
- 删除返回 `202` 后保持进度反馈，只有服务端确认清理完成才从列表移除。
- 确认对话框打开后焦点进入对话框，关闭后回到触发按钮。

### 11.5 监控页

- 阶段按固定顺序展示：`environment_scan`、`code_analysis`、`vulnerability_verify`、`report_generate`、`done`。
- 六类角色使用统一名称和状态，不根据事件到达顺序改变排列。
- 消息、日志和资源使用独立区域，任一区域失败不影响其他区域。
- 日志支持级别筛选、暂停自动滚动、回看历史和复制单行脱敏内容。
- ECharts 图表同时提供当前数值、单位、时间范围和文本摘要。
- 新漏洞提示不得遮挡停止操作和错误信息。

### 11.6 漏洞与攻击路径

- 风险顺序固定为 `critical`、`high`、`medium`、`low`、`info`。
- 验证状态固定为 `pending`、`verified`、`rejected`。
- 漏洞列表筛选同步到 URL，不在前端对不完整分页结果做全量统计。
- 文件位置按纯文本展示，可提供受控复制，不生成 `file://` 链接。
- 证据、复现步骤和验证代码使用转义后的预格式化文本；代码高亮器如需引入必须单独评审安全性和包体积。
- 攻击路径按 `step_order` 稳定排序，关联漏洞只允许跳转到同项目详情路由。
- 缺失关联资源时展示数据异常，不猜测或跨项目请求。

### 11.7 报告

- `pending`、`generating`、`ready`、`failed` 使用不同页面状态。
- 报告未就绪时禁用下载，不创建无效下载请求。
- Markdown 默认以转义文本或安全渲染结果展示。
- HTML 预览只使用后端已清理的 `report_html`，放入隔离的报告容器，不允许脚本、事件属性、内联表单和危险 URL。
- 除报告预览组件外禁止使用 `v-html`。
- 报告生成失败时保留漏洞和攻击路径入口，并展示脱敏错误及 `request_id`。

### 11.8 错误反馈

- 用户可纠正的错误说明原因和下一步操作。
- 网络中断区分“请求失败”和“后台任务失败”。
- `409` 显示当前状态冲突并提供刷新入口。
- `422` 映射字段错误，无法映射的错误显示在表单顶部。
- `429` 展示可重试时间并临时禁用对应操作。
- `500` 和 `503` 不自动高频重试写操作，保留 `request_id` 供排查。
- 不向用户展示后端堆栈、对象序列化结果或英文库错误。

## 12. 样式与响应式布局

### 12.1 样式组织

- 全局样式只包含重置、主题变量、排版、焦点样式和少量布局基础类。
- 组件样式默认使用 `scoped`，跨组件主题通过 CSS 自定义属性实现。
- 禁止在业务模板中大量使用内联样式。
- 颜色、间距、字号、圆角、阴影和层级必须来自设计变量。
- `z-index` 使用集中定义的层级，不以不断增大的随机数字解决遮挡。
- 不通过 `!important` 常规覆盖 Element Plus；确需覆盖时限制作用域并说明原因。

### 12.2 响应式基线

MVP 是桌面 Web 应用，验收基线为 1440×900 及以上，仍必须支持常见桌面窗口缩放：

- 1440 像素及以上：展示完整导航、双栏或多栏监控布局。
- 1024 至 1439 像素：折叠次要侧栏，卡片网格减少列数，主操作保持可见。
- 小于 1024 像素：不属于 MVP 专项验收范围，但登录、基础查看和关键提示必须可读，不得直接阻断访问。
- 表格在空间不足时水平滚动，固定标识列和操作列，不压缩到内容不可读。
- 监控面板按业务优先级换行，不通过固定宽度造成页面整体溢出。
- 弹窗宽度使用视口约束，内容区可滚动，操作区保持可达。

CSS 断点统一定义，禁止各页面自行发明相近断点。

### 12.3 内容稳定性

- 页面加载时为表格、图表和报告区域预留合理空间，减少布局跳动。
- 长项目名、路径、日志和错误信息必须换行或省略，并提供查看完整内容的可访问方式。
- 状态变化不得导致主要操作按钮在页面中剧烈跳位。
- 字体图标加载失败时仍保留文字或可访问名称。

## 13. 无障碍访问

### 13.1 基线

核心流程应达到 WCAG 2.1 AA 的可操作基线：

- 所有操作可通过键盘完成。
- 焦点顺序与视觉顺序一致。
- 焦点样式清晰，不得全局移除 `outline`。
- 正文和交互文本满足对比度要求。
- 状态不仅通过颜色表达，还包含文本或图标说明。
- 页面缩放到 200% 时核心操作仍可使用。

### 13.2 表单与弹窗

- 输入框必须有明确标签、格式说明和错误关联。
- 错误摘要可聚焦，并提供到具体字段的跳转。
- 弹窗使用焦点陷阱，支持 `Escape` 关闭非强制流程。
- 关闭弹窗后恢复触发点焦点。
- 破坏性操作的确认按钮文案必须具体，例如“删除项目”，不得只写“确定”。

### 13.3 实时内容

- 项目和阶段的重要状态变化使用节制的 `aria-live="polite"` 通知。
- 高频日志、资源采样和 token 变化不得逐条向屏幕阅读器播报。
- 自动滚动区域必须允许暂停。
- 新漏洞提示应可关闭且不抢夺当前输入焦点。
- 图表必须提供同等信息的文本摘要或数据表入口。

### 13.4 动效

- 动效只用于表达状态和层级，不延迟核心操作。
- 尊重 `prefers-reduced-motion`，减少或关闭非必要动画。
- 加载动画不得快速闪烁，不使用可能诱发不适的效果。

## 14. 前端安全

### 14.1 XSS 与内容安全

- 日志、消息、证据、路径、任务输出和 Markdown 默认使用文本插值，禁止拼接 HTML。
- 除受控报告预览外禁止 `v-html`。
- 即使后端声明已清理 `report_html`，前端仍应限制容器能力，不为内容绑定事件。
- 外部链接只允许 `http` 和 `https` 协议，使用新窗口时增加 `noopener`、`noreferrer`。
- 禁止把用户或模型输出传给 `eval`、`Function`、动态脚本、动态样式或不受控 URL。
- 配合 Nginx 启用内容安全策略；前端不得依赖内联脚本。

### 14.2 敏感数据

- 密码输入禁止回显、日志记录和状态持久化。
- Cookie、CSRF Token、仓库凭证和内部绝对路径不得写入日志、错误上报或浏览器存储。
- 仓库地址展示前使用服务端脱敏值，前端不得尝试还原凭证。
- 复制日志、证据和报告内容时保留服务端脱敏结果，不额外拼接内部元数据。
- 登出后清理内存数据、会话缓存、下载对象 URL 和实时连接。

### 14.3 请求安全

- 所有受保护请求同源发送 Cookie。
- 写请求按接口契约携带 CSRF 和幂等头。
- 报告下载和项目子资源请求必须走受权 API，不访问文件系统路径。
- 路由权限、按钮可见性和字段禁用只用于体验，不能当作安全控制。
- 前端不得调用内部 Worker、Executor、Redis、PostgreSQL 或 Docker 接口。

## 15. 性能与浏览器兼容

### 15.1 性能要求

- 页面路由按模块懒加载，ECharts 和报告预览等大模块按需加载。
- 首屏不得加载监控、漏洞、攻击路径和报告页的全部代码。
- 大列表使用服务端分页；日志 DOM 行数必须受控。
- 过滤、格式化和图表数据转换避免在模板每次渲染中重复执行。
- 大对象不使用无必要的深度响应式；只读数据可使用浅层响应式或不可变更新。
- 资源图表批量刷新，页面不可见时降低渲染频率。
- 图片和非关键资源设置明确尺寸并按需加载。
- 合并前检查构建分包和异常体积增长；新增大型依赖必须说明收益和替代方案。

### 15.2 网络策略

- 不对非幂等写操作进行无条件自动重试。
- 查询接口只对短暂网络错误进行有限重试，并加入退避。
- 多区域首屏数据可并发请求，存在依赖的数据必须串行。
- 用户离开页面后取消无用请求。
- 不使用高频轮询替代可用的 WebSocket；断线补偿轮询必须有上限并在连接恢复后停止。

### 15.3 浏览器兼容

- 支持 Chrome、Edge、Firefox 和 Safari 最新两个稳定版本。
- 浏览器目标统一配置在构建配置中，不在源码分散判断 User-Agent。
- 使用新 Web API 前检查目标浏览器支持情况；必要时采用小型、按需的 polyfill。
- 不依赖仅 Chromium 支持的文件、滚动或网络行为。
- Playwright 至少覆盖 Chromium；关键发布版本应补充 Firefox 和 WebKit 冒烟测试。
- 在 1440×900 基线和 1024 像素宽窗口执行布局回归。

## 16. 测试规范

### 16.1 测试分层

| 层级 | 工具 | 重点 |
| --- | --- | --- |
| 纯函数 | Vitest | 格式化、状态映射、排序、事件归并和边界校验 |
| Composable | Vitest | 请求生命周期、取消、重连、去重和资源释放 |
| Store | Vitest | 状态转换、并发请求、认证失效和项目切换 |
| 组件 | Vue Test Utils | 渲染、输入、事件、加载、空态、错误态和可访问名称 |
| 页面集成 | Vue Test Utils | Router、Pinia、API Mock 和权限分支 |
| 端到端 | Playwright | 真实路由、关键业务流程、下载和实时更新 |

### 16.2 必测业务

P0 自动化测试至少覆盖：

- 未初始化系统进入初始化页，重复初始化被拒绝。
- 正确和错误凭证登录，登录过期后回到登录页。
- 普通用户无法进入系统配置页。
- 使用本地路径和仓库地址创建项目。
- `created` 项目启动，重复启动显示冲突。
- `running` 项目停止并等待收敛为 `stopped`。
- 运行中项目无法删除，非运行项目完成二次确认后删除。
- 监控页应用 REST 快照和 WebSocket 增量事件。
- WebSocket 重连、重复事件、序号跳跃和 `4009` 全量补偿。
- 漏洞筛选、漏洞详情和同项目攻击路径跳转。
- 报告未就绪时禁用下载，报告就绪后预览和下载。
- 日志、证据和报告中的脚本内容不会执行。
- 关键页面的键盘操作、焦点恢复和可访问名称。

### 16.3 测试规则

- 测试名称描述用户可观察行为，不复述函数名。
- 不依赖真实时钟、随机 UUID 和网络；通过可注入实现或 Mock 固定。
- WebSocket 测试必须模拟乱序、重复、断线、关闭码和高频事件。
- 不用大面积快照测试代替行为断言。
- 修复缺陷时必须先增加可复现测试，无法自动化时说明原因和人工步骤。
- E2E 测试数据相互隔离，可重复运行，不依赖执行顺序。
- 测试中不得写入真实密码、Token、私有仓库地址和生产服务地址。

## 17. 质量门禁

### 17.1 标准脚本

`packages/asa-ui/package.json` 必须提供以下脚本，根目录可提供对应聚合脚本：

```json
{
  "scripts": {
    "format": "prettier --write .",
    "format:check": "prettier --check .",
    "typecheck": "vue-tsc --noEmit",
    "lint": "eslint . --max-warnings=0",
    "test:unit": "vitest run",
    "test:e2e": "playwright test",
    "build": "vite build"
  }
}
```

具体命令可因工作区路径调整，但脚本名称和职责必须保持稳定。

### 17.2 合并前检查

每次前端变更合并前必须依次完成：

```bash
pnpm --filter @asa/ui format:check
pnpm --filter @asa/ui typecheck
pnpm --filter @asa/ui lint
pnpm --filter @asa/ui test:unit
pnpm --filter @asa/ui build
pnpm test:e2e
```

若仓库最终未选择 `pnpm`，使用锁文件对应的包管理器执行同名脚本，不得跳过检查。

以下任一情况不得合并：

- 格式、类型、Lint、单元测试、E2E 或生产构建失败。
- ESLint 存在 Warning。
- 通过跳过测试、关闭规则、放宽类型或更新无关快照掩盖失败。
- P0 流程只完成成功路径，未处理加载、空态、错误、冲突和权限状态。
- 新增用户可见文案、状态或接口字段但未更新对应契约或测试。

### 17.3 变更说明

前端交付说明必须包含：

- 关键改动和影响页面。
- 接口、契约、路由、Store 或组件边界变化。
- 已执行的格式化、类型检查、Lint、测试和构建命令及结果。
- 响应式、无障碍和浏览器验证范围。
- 已知限制、潜在安全或性能风险。
- 需要后端、测试、部署或产品共同确认的事项。

不得使用“无风险”替代判断。确实未发现风险时，应说明核查范围和仍未覆盖的环境。

## 18. 代码评审清单

### 18.1 架构与类型

- 是否遵循 `packages/asa-ui`、`packages/contracts` 和模块目录边界。
- 是否存在跨模块读取内部文件、循环依赖或重复状态。
- API 和事件是否使用契约类型，是否出现 `any`、不安全断言或手写重复枚举。
- 组件、Composable、Store 和 Service 的职责是否清晰。
- 是否存在只使用一次的过度抽象或多个重复实现。

### 18.2 业务与交互

- 页面是否覆盖加载、空态、错误、权限和冲突。
- 项目状态与可执行操作是否符合状态机。
- 异步受理是否正确区分“已受理”和“已完成”。
- 停止、删除是否二次确认并使用正确幂等 Key。
- 页面刷新、项目切换和 WebSocket 断线后是否可恢复。

### 18.3 安全与隐私

- 是否安全展示日志、证据、报告和外部 URL。
- 是否新增 `v-html`、动态脚本、内联凭证或不受权文件访问。
- Cookie、CSRF、密码和项目敏感数据是否进入浏览器持久化或日志。
- 普通用户是否可能通过页面路径看到管理员功能。

### 18.4 质量与体验

- 是否使用语义化 HTML，键盘和焦点流程是否完整。
- 是否在 1440×900 和窄桌面窗口验证响应式布局。
- 是否控制日志 DOM、资源图表和分包体积。
- 是否补充与变更风险相匹配的单元、组件和 E2E 测试。
- 格式、类型、Lint、测试和生产构建是否全部通过。

## 19. 已知边界与待确认事项

以下事项尚未在 PRD 和概要设计中最终确定，前端不得写死：

- 普通用户账户创建、禁用和密码重置流程。
- 当前用户和会话恢复接口；现有接口不足以在页面刷新后可靠恢复用户名与角色，不得通过访问配置接口是否返回 `403` 来推断角色。
- 项目共享与跨用户授权模型。
- 私有 Git 仓库凭证托管及前端交互方式。
- `environment_type` 的最终值域。
- 会话有效期、密码强度和登录失败锁定策略。
- WebSocket 心跳周期、空闲超时和事件保留窗口。
- WebSocket 全量补偿后的最新项目事件序号获取方式；重新订阅前必须由服务端提供明确序号，不得使用日志或消息游标代替。
- 日志、消息和资源接口的最大时间窗口。
- 报告是否增加 PDF 格式。
- 移动端完整交互和专项验收标准。

未确认项必须通过后端下发配置、契约类型或模块边界隔离。开发中发现契约无法支撑页面闭环时，应先更新设计和接口文档，不得在前端以临时字段、模拟状态或硬编码数据长期绕过。
