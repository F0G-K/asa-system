# 攻击路径模块（attack_paths）

## 1. 模块概述

### 1.1 定位

`attack_paths` 模块负责将同项目内的多个漏洞串联为可复现的攻击链——描述攻击者从初始访问到最终影响的完整利用路径。每条路径按步骤顺序关联漏洞，并展示每个步骤的攻击行为和最终的危害结论。

### 1.2 设计依据

- `docs/1_PRD/自动化安全评估系统-PRD.md`
- `docs/3_概要设计/自动化安全评估系统-概要设计总纲.md` — 第 5.2 节、第 8.6 节
- `docs/4_开发规范/API接口文档.md` — 第 7.3-7.4 节（攻击路径接口）
- `docs/4_开发规范/后端/后端开发规范.md` — 第 9.4 节（领域异常）
- `docs/4_开发规范/数据库/数据库设计.md` — `attack_paths`、`attack_path_items` 表设计

### 1.3 职责边界

| 职责 | 说明 |
| --- | --- |
| 路径创建 | 将多个同项目漏洞按利用顺序串联为攻击路径 |
| 步骤管理 | 保存每条路径的连续步骤，每步关联一个漏洞 |
| 路径查询 | 提供分页列表和详情查询 |
| 约束保证 | 路径必须至少一个步骤，步骤从 1 连续，漏洞必须同项目 |

**不负责：** 漏洞发现和验证（vulnerabilities）、攻击路径自动发现（agents/report_editor）——这些由对应模块处理。

## 2. 架构与依赖

### 2.1 涉及的数据库表

| 表 | 角色 |
| --- | --- |
| `attack_paths` | 路径主表：标题、摘要、最终影响 |
| `attack_path_items` | 步骤表：按 `step_order` 连接路径与同项目漏洞 |
| `vulnerabilities` | 被关联的漏洞（引用） |
| `worker_tasks` | 关联生成任务 |

### 2.2 涉及的 API 接口

| 接口 | 方法 | URL | 说明 |
| --- | --- | --- | --- |
| 查询攻击路径列表 | `GET` | `/api/v1/projects/{project_id}/attack-paths` | 分页、关键词搜索 |
| 查询攻击路径详情 | `GET` | `/api/v1/projects/{project_id}/attack-paths/{attack_path_id}` | 含完整步骤和关联漏洞摘要 |

## 3. 领域模型

### 3.1 攻击路径实体

```text
AttackPath
├── id: UUID
├── project_id: UUID
├── created_by_task_id: UUID?
├── path_code: str                  # 路径编号，如 "PATH-2026-001"
├── path_title: str                 # 路径标题
├── path_summary: str               # 路径摘要
├── final_impact_text: str          # 最终影响
├── created_at: datetime
└── updated_at: datetime

AttackPathItem (步骤)
├── id: bigint
├── project_id: UUID                # 防止跨项目关联
├── path_id: UUID                   # 所属路径
├── vuln_id: UUID                   # 关联漏洞
├── step_order: int                 # 从 1 连续编号
├── step_text: str                  # 步骤说明
└── created_at: datetime
```

### 3.2 业务规则

| 规则 | 实现方式 | 说明 |
| --- | --- | --- |
| 路径至少一个步骤 | 延迟约束触发器 | 提交时检查 `COUNT(*) >= 1` |
| 步骤从 1 连续 | 延迟约束触发器 | 提交时检查 `step_order` 无间隙 |
| 路径编号项目内唯一 | `(project_id, path_code)` UNIQUE | 数据库约束 |
| 漏洞必须同项目 | 复合外键 `(vuln_id, project_id)` | 数据库层阻止跨项目关联 |
| 同路径不重复关联同漏洞 | `(path_id, vuln_id)` UNIQUE | 数据库约束 |
| 步骤顺序唯一 | `(path_id, step_order)` UNIQUE（延迟） | 允许事务内重排 |

### 3.3 领域异常

| 异常 | HTTP 状态 | 业务码 |
| --- | --- | --- |
| `AttackPathNotFound` | 404 | `ATTACK_PATH_NOT_FOUND` |
| `AttackPathEmpty` | 422 | 路径至少需要一个步骤 |
| `AttackPathStepDiscontinuous` | 422 | 步骤编号不连续 |
| `AttackPathCrossProjectVulnerability` | 422 | 关联的漏洞不属于当前项目 |

## 4. 数据一致性设计

### 4.1 创建流程

```text
创建攻击路径（同一事务内完成）：
  │
  ├── 1. INSERT attack_paths (path_code, path_title, ...)
  ├── 2. 循环 INSERT attack_path_items (step_order=1,2,...,n)
  │     每个 item 校验 vuln_id 对应的漏洞 project_id 一致
  ├── 3. 延迟约束在 COMMIT 时校验：
  │     ├── 至少一个步骤
  │     └── step_order 从 1 连续无间隙
  └── 4. COMMIT
```

### 4.2 数据库层防御

```sql
-- 攻击路径步骤的复合外键（每个步骤都强制项目一致性）
ALTER TABLE attack_path_items
  ADD CONSTRAINT fk_attack_path_items__path__attack_paths
    FOREIGN KEY (path_id, project_id)
    REFERENCES attack_paths (id, project_id);

ALTER TABLE attack_path_items
  ADD CONSTRAINT fk_attack_path_items__vuln__vulnerabilities
    FOREIGN KEY (vuln_id, project_id)
    REFERENCES vulnerabilities (id, project_id);

-- 同路径不重复关联同漏洞
ALTER TABLE attack_path_items
  ADD CONSTRAINT uq_attack_path_items__path_vuln
    UNIQUE (path_id, vuln_id);

-- 步骤顺序唯一（延迟）
ALTER TABLE attack_path_items
  ADD CONSTRAINT uq_attack_path_items__path_step
    UNIQUE (path_id, step_order)
    DEFERRABLE INITIALLY DEFERRED;
```

### 4.3 删除级联

- 删除攻击路径 → `attack_path_items` CASCADE 删除（步骤没有独立生命周期）。
- 删除漏洞 → 关联的 `attack_path_items` CASCADE 删除（路径自动缩短，如步骤不连续路径仍存在需由报告阶段处理）。

## 5. 查询实现

### 5.1 路径列表

```text
GET /api/v1/projects/{project_id}/attack-paths
  ?page=1&page_size=20&keyword=越权&sort=created_at:desc

查询条件：
  ├── WHERE project_id = :project_id
  └── AND (path_code ILIKE :kw OR path_title ILIKE :kw) ← 可选

返回字段：
  ├── id, path_code, path_title, path_summary, final_impact_text
  ├── step_count（子查询或 JOIN 计算）
  ├── vulnerability_codes（关联漏洞编号数组）
  └── created_at

索引：ix_attack_paths__project_id_created_at
```

### 5.2 路径详情

```text
GET /api/v1/projects/{project_id}/attack-paths/{attack_path_id}

校验：
  ├── project_id 和 attack_path_id 为有效 UUID
  └── 路径的 project_id 与 URL project_id 一致

返回：
  ├── 路径基本信息
  └── steps[] 按 step_order 升序：
        ├── step_order, step_text
        └── vulnerability: { id, vuln_code, vuln_title, risk_level, verify_status }
```

## 6. 代码实现指南

### 6.1 目录结构

```text
packages/backend-core/src/asa_core/domain/attack_paths/
├── entities.py              # AttackPath, AttackPathItem 聚合
├── value_objects.py         # PathCode, StepOrder
├── validators.py            # StepContinuityValidator, CrossProjectValidator
└── exceptions.py            # AttackPathNotFound, AttackPathEmpty

packages/backend-core/src/asa_core/application/
├── commands/
│   └── create_attack_path.py    # CreateAttackPath (事务内创建路径+全部步骤)
├── queries/
│   ├── list_attack_paths.py     # ListAttackPaths
│   └── get_attack_path_detail.py # GetAttackPathDetail
└── ports/
    └── attack_path_repository.py

apps/api/src/asa_api/routers/v1/attack_paths.py
apps/api/src/asa_api/schemas/attack_paths.py
```

### 6.2 关键实现约束

- **路径和全部步骤在同一事务创建**。不允许先创建路径、后逐条添加步骤的跨事务操作。
- **复合外键是数据库层的防御**，不允许只依赖应用层检查同项目关联。
- **`step_order` 从 1 连续**：使用延迟唯一约束 + 延迟触发器校验。批量重排也必须在一个事务内完成。
- **路径详情中的漏洞不返回完整证据文本**，只返回摘要信息。
- 路径列表的 `step_count` 和 `vulnerability_codes` 通过 JOIN 或子查询计算，不在 `attack_paths` 表中冗余存储。

## 7. 安全要点

- 路径和步骤查询同时校验 `project_id` 和用户权限。
- 复合外键在数据库层阻止跨项目关联漏洞（即使应用层代码有 bug，数据库也会拒绝）。
- 路径详情中的漏洞信息只返回摘要（`id`、`vuln_code`、`vuln_title`、`risk_level`、`verify_status`），不返回完整证据。

## 8. 测试要点

### 8.1 单元测试

- 步骤连续性校验：`[1,2,3]` 合法，`[1,3]` 不合法，`[2,3]` 不合法（不从 1 开始）
- 空步骤拒绝
- 跨项目漏洞拒绝（领域层校验）
- 路径编号格式

### 8.2 API 测试

- `GET /api/v1/projects/{project_id}/attack-paths` — 分页、关键词搜索、空结果
- `GET /api/v1/projects/{project_id}/attack-paths/{id}` — 成功、路径不存在（404）、跨项目访问（404）
- 步骤按 `step_order` 升序返回
- 每个漏洞 `project_id` 与路径 `project_id` 一致

### 8.3 数据库集成测试

- 复合外键：插入跨项目漏洞步骤 → 数据库拒绝
- 延迟唯一约束：事务内重排步骤后提交成功
- 约束触发器：提交空步骤路径 → 数据库拒绝
- 约束触发器：提交不连续步骤 → 数据库拒绝
- 删除漏洞级联删除关联步骤
- 删除路径级联删除全部步骤
